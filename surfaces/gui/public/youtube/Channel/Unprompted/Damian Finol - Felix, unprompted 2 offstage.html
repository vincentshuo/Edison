五百个网关与一把凿子

Enterprise OpenClaw at Scale — Damian Finol (Félix), [un]prompted 2, 2026 offstage

十二分钟的访谈，讲的是一个问题：Agent 进了企业之后，到底该怎么跑。Félix 工程副总裁 Damian Finol 坐在 [un]prompted 的红色沙发上，讲他在公司内部署了 500 多个 OpenClaw 网关——客服报单的排查从一小时缩到几分钟，员工内网里的 Agent 会替他预审 PR、攒好上下文再来打断他，改个按钮颜色全程在 Slack 里完成，没人打开过 IDE。他最得意的比喻是两把工具：给全公司一把锤子，有人造书架，有人造床；拿到一整块能跑的“AI slop”，再由人一凿一凿凿出能用的软件。他的结论是，开发范式已经变了，技术债不再事后还，改成先付。

Key Takeaways

  1. 规模本身就是论点。500 多个 OpenClaw 网关跑在企业里；Finol 来 [un]prompted，就是请同行来挑刺，好给它加防护。
  2. 一小时变几分钟。客服在 Slack 里报单查不到，Agent 两三分钟内给出整条链路与修复 PR；工程师只花四五分钟验证。
  3. Agent 的价值在“我们”，不在“我”。员工内网里的 Agent 会预审 PR、攒好上下文，专治打断与上下文切换。
  4. 多人编码：没人打开过 IDE。Slack 线程里改按钮颜色，Agent 直接出代码与 PR，人在健身房里接着改，全程没开 Codex、Cursor 或 VS Code。
  5. 开发范式变了。从一块块往上加的乐高，变成先拿到一整块能跑的“AI slop”，再用人来凿；技术债改成先付。

1. 开场：带着 500 个网关来求挑刺

主持人 Aaron Mog 开场先道谢，请 Damian Finol 向不认识他的人介绍自己。Finol 说，他是 Félix 的工程副总裁。这家 C 轮金融科技公司的目标，是帮在美国的拉丁裔移民与拉丁美洲的家人保持联结——汇款、贷款一类的金融工具。他管的是工程运营：IT、安全、基础设施、质量与企业级 AI，摊子不小。

Finol 住在洛杉矶，来旧金山只要一趟短途航班。他说自己做安全 30 年了，今年 43 岁，以前在 Defcon 讲过话，喜欢安全、喜欢折腾、喜欢好奇心被点燃的时刻。他这次带来一个演讲，讲的是公司内部正在部署、正在用的东西——来 [un]prompted，一半是分享，一半是请同行评审：要是有人能说“我能这么黑进去”，他好回去加防护。演讲题为《企业级 OpenClaw：大规模应对 Agent 安全》，定在次日下午 15:30、Stage 1。他还开了个玩笑：开讲之前，最好先把救护车备好。

2. 先讲规模：开源、非营利基金会与一层层防护

演讲的核心数字先抛了出来：Félix 的企业级部署里跑着 500 多个 OpenClaw 网关。Mog 倒吸一口气。Finol 说，OpenClaw 是开源的，大约一年前发布，如今由一家非营利基金会管理。很多人用它做很深的 Agent 用例，而他关心的是另一个方向：怎么把它铺得够宽，铺到足够多的人手里——然后再一层层过安全关：防提示词注入、防自我修改、防混淆代理人，防 Agent 把令牌与凭证外泄。

■ OpenClaw：开源 AI 助手，跑在自己的机器或服务器上，经由 Slack、WhatsApp 等聊天应用对话；2025 年 11 月以 Clawdbot 之名发布，2026 年 1 月改名，7 月起由 OpenClaw Foundation（美国 501(c)(3) 非营利组织）管理。

■ 提示词注入（Prompt Injection）：通过输入内容诱使 Agent 做出超出授权的操作，是 Agent 安全最常见的攻击面之一。

■ 混淆代理人（Confused Deputy）：Agent 被诱导着动用自己的权限替攻击者办事的经典安全问题；Finol 把它与提示词注入、自我修改并列为部署时必须防住的三类风险。

这套部署已经长出了 Finol 自己都没想到的用法。公司每周有一次内部展示，员工轮流演示用内部 Agent 机器人 Maestro 做的新东西，他常常听得一愣：“等等，你拿它做了什么？”他的比喻是锤子：“我给他们一把锤子，有人造书架，有人造床，有人造出别的东西。”他的乐趣正在于看成品送到眼前——“你居然拿它做了这个。”

■ Maestro：Félix 内部 Agent 机器人的名字，全公司员工都可以用它；每周展示会上，员工演示用它做出的新东西。

Finol 并不讳言眼下的状态。他说，现在是“YOLO 安全”的时代：把文档丢进上下文，Agent 不会拦你。但把这种程度的 Agent 基础设施部署在一家金融科技公司里，可不是小事——“不是说着玩的”。

“I want to make sure that we have ambulances ready tomorrow afternoon when I start talking.”明天开讲之前，我得先确保救护车就位。

3. 最快的一单：客服报单，一小时变几分钟

Mog 请他挑一个最能说明问题的用例。Finol 选了客服报单。客服团队有个 Slack 频道，客服坐席在里面贴“这单没送达”之类的消息。以前，产品工程师要拿着订单号一个系统一个系统地查：这单到这儿了、那儿没付、状态又切到那儿了，查下来要一个小时。如今，频道里放了一个 Agent，它知道上下文、知道各服务、接上了 GitHub、New Relic 等内部系统。客服坐席说“这单没付”之后两三分钟，Agent 已经把整条链路摆出来了：这儿超时了、那儿有个竞态条件，在第 18 行，修法是改数据库里的订单状态——“要不要我提个 PR 修掉这个竞态问题？”产品工程师现在只花四五分钟验证一遍。

■ 竞态条件（Race Condition）：两个操作抢着读写同一份数据、结果取决于谁先谁后的缺陷；此处是 Agent 在订单链路里定位到的具体问题。

从一小时到几分钟，省下的不只是时间。Finol 的算法很直白：单子一多，省下来的工程小时数就很可观。但他最喜欢的还不是这一单。

4. 最喜欢的一单：会预审 PR 的 Agent

他最喜欢的是员工内网里的 Agent。公司内网有个员工名录，每个人旁边都挂着一个小 Agent，可以问这个人在做什么、做到哪一步、卡在哪里。工程师点开 Finol 的主页，能问“Damian 在忙什么”，Agent 会说：这是他的 ClickUp、GitHub、Notion，他正在盯这几件事；甚至可以直接问“能让 Damian 审一下我的 PR 吗？”Agent 会按 Finol 喜欢的模型与评审参数先预审一遍，再把请求放进他的待办清单。

这件事的价值不在省了几分钟，而在治打断。工程师与员工最大的时间税就是上下文切换——“不好意思打断一下，能帮我做这个吗？能帮我做那个吗？”现在是：先去问我的 Agent，Agent 预审、攒好上下文，只在真正需要打断他的时候才来找他，附上全部上下文。等到他审 PR 时，上下文已经齐了，他只要看一眼、点通过。Finol 说，这几乎就是一个很好的助理。

“What can our agents do for us?”我们的 Agent 能为我们做什么？

这也是他对 Agent 提问方式的修正：大家总在问“我的 Agent 能为我做什么”，而他更关心的是“我们的 Agent 能为我们做什么”。人不是独自工作的，Agent 也不该只服务一个人——它该服务一群人之间的协作。

5. 多人编码：Slack 里改按钮，没人打开 IDE

Mog 追问：作为一个走在最前沿的人，他最近在为什么兴奋？Finol 的答案是 Agent 带来的全新工作流。Agent 能做渗透测试、能在代码里找漏洞、能逃出沙箱——这些他都不展开了。让他兴奋的是 OpenClaw 在公司内部启用的一种做法：多人编码。工作不再是串行的了，一切都被并行化了。

例子很具体。有人在 Slack 线程里写一句“这个按钮不该是绿的，该是蓝的”，Agent 立刻动手，写代码、提 PR、贴回 Slack 频道。另一个工程师可能正在健身房，补一句“不对，不是翠绿，是深绿；不是深蓝，是浅蓝”，Agent 再改、再提 PR。然后大家审一遍、点批准。Finol 替全场数了一遍：“我们打开 Codex 了吗？打开 Cursor 了吗？打开 VS Code 了吗？什么都没打开。”一群人就在 Slack 里把活干完了，Agent 领着路。

■ 多人编码（Multiplayer Coding）：多人在同一 Slack 线程里指挥同一 Agent 改代码、互相接力，Agent 负责出代码与 PR；Finol 认为这是传统串行开发之后的新范式。

“Did we open Codex? Did we open Cursor? Did we open VS Code? We didn’t open anything.”我们打开 Codex 了吗？打开 Cursor 了吗？打开 VS Code 了吗？什么都没打开。

这正是他想在 [un]prompted 听到的东西：从传统软件开发生命周期到智能体式软件开发生命周期，别人是怎么落地的。这套东西太新了，谁也不知道六个月后会走到哪一步——而 [un]prompted 如今每季度办一次，正好够跟上这个速度。

6. 从乐高到凿刻：技术债改成先付

Finol 曾经是大学教授，教的就是软件开发方法论。如今他看的是新方法论长出来的样子。过去四十年，写代码一直是加法：加一行、加一个类、加一个文件，意图明确；当然也有残次与 Bug，但方向是往上加。就像搭乐高，一块砖一块砖往上垒。

智能体式开发反过来了：你先拿到一整块能跑的“AI slop”，然后得把它一凿一凿凿下来，用对抗评审一类的方法，凿出最终能交付的东西。过去那套加法时代的方法——冲刺规划、敏捷——在这个环境里不灵了。真正的问题变成了：用什么技术围住它——怎么做安全、怎么做质量控制、怎么做评审、怎么上线、怎么做金丝雀发布。Finol 的说法是：现在是先付技术债。

■ 智能体式软件开发生命周期（Agentic SDLC）：先由 Agent 生成一整块能跑的代码，再由人凿刻、评审、收紧的开发方式，与传统逐行累加的 SDLC 相对；Finol 认为冲刺规划与敏捷在这种环境里不再适用。

“You start with a block of AI slop.”你先拿到一整块 AI slop。

访谈收在 Finol 的邀请里：他很期待有人站出来说“我能这么黑进去”——“来，证明我错了。”对他而言，这正是 [un]prompted 值得来的原因：满屋子都是对 AI 前沿有看法的人，而他带来的，恰恰是最前沿里最难的那一块。
