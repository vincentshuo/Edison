一位开发者，二十年，三千万用户之后

One Developer, Two Decades, and 30 Million Users Later

Speaker: Philip Guo，加州大学圣地亚哥分校认知科学教授

Event: Stanford CS547 HCI 研讨会，2026 年秋季（Gates B3）

Technical Monograph · 精读报告 发布 2026 年 11 月 20 日 生成 2026 年 11 月 21 日

二十年前，郭走进斯坦福读计算机博士；二十年后，他回到同一间研讨会教室，讲一个人的副业如何变成近三千万人在 180 多个国家使用的教学工具。Python Tutor 不过是把代码一行一行跑给你看，把变量、对象、指针与栈帧画成图——可正是这个"显而易见"的主意，让它活过了慕课大潮、熬过了十年的用户增长，又在生成式 AI 的冲击下重新回答自己为什么还存在。本报告按演讲的三幕结构还原这段旅程：初创、加速、颠覆，以及贯穿始终的一条手艺人的信条——先把东西做好，再把它一直做好。

Key Takeaways

  1. 工具的使命是帮新手建立心智模型。代码对初学者是个黑盒子，教师靠手绘板书照亮它；电脑既然在跑代码，本也可以顺手把图画出来。
  2. 外行人的位置反而是优势。没有基金、团队、新颖性与评估的包袱，四天做出第一版、直接挂上网，零安装、零账号、零门槛，这才让它活下来。
  3. 长寿靠手艺，不靠增长。先把东西做好，让人一见钟情、主动分享；再对大多数功能请求说不，让约束逼出清晰的焦点。
  4. 增长会毁掉好东西。讨好老板、资方、评审这些非用户，只会让产品偏离使命；守住"帮新手建立心智模型"这一条主线，才是抵抗劣化的办法。
  5. AI 既是颠覆，也是复兴。用户量下滑、克隆站泛滥、界面显旧，但理解代码的需求没有消失；把 AI 当作执行团队、把自己当作产品经理，手艺的审美与关怀反而更值钱。

1. 开场：一道小测验，代码是个黑盒子

演讲开场没有寒暄，只有一句"回到这里真好"。郭说，他 2006 年秋天走进斯坦福读计算机博士，整整二十年前，也是在这样的研讨会教室里，坐在台下听人讲人机交互——当时他对这个领域几乎一无所知。二十年后他站上讲台，身边放着一张实时地图：此刻正有人在世界各地打开 Python Tutor，一步一步看代码运行；旁边还有一张过去 24 小时的用量图，亮点随著时区切换而移动。这不是装饰，而是整场演讲的论点本身：一个人的副业，二十年后仍在被全世界使用。

他随即给全场出了一道小测验。屏幕上是一段短短的代码：x = [1, 2, 3]；y = x；y.append(4)；print(x)。问：它会打印出什么？台下有人答 1 2 3 4，有人答 1 2 3。两个答案都对，也都不对——答案取决于语言。在许多语言里它打印 1 2 3；在 Python 里，y = x 不是复制整张表，而是让 y 指向同一张表，于是 y.append(4) 之后，print(x) 得到 1 2 3 4；到了 C++，答案又取决于变量是怎么声明的。这道题的用意不在考语法，而在揭示一个事实：初学者面对代码时，脑子里并没有一幅可靠的图景，只能靠猜。

郭把学编程的过程归结为一句话：把代码丢进一个神秘的盒子，看它吐出什么，再试一次，再试一次，从结果里反推盒子里的规矩。"外行人听了会问，这样谁学得会？"他说。而教师的工作，就是帮新手建立关于代码如何运行的有用的心智模型。教师最自然的做法，是在黑板上画图，一步一步拆解。可问题随之而来：电脑明明已经在运行这段代码，为什么它不能顺手把图也画出来？

“Why can’t the computer also draw the diagrams too?”电脑既然在跑代码，为什么不能顺手把图也画出来？

这句反问就是 Python Tutor 的全部起点。郭说，这场演讲不是传统的研究报告，而是一次个人回顾：一个只有一名开发者的项目，如何从零走到今天；以及它凭什么没有像同时代成百上千个在线教育产品那样悄悄消失。他把这段旅程分成三幕：初创、加速、颠覆。

2. 工具本身：一步一步，看见代码在干什么

Python Tutor 的用法朴素到近乎简陋：打开 pythontutor.com，写一段代码，点运行，网站自动把每一步执行画成图。郭在现场重跑了开场那道测验：第一行执行后，全局帧里出现变量 x，指向一个写著 1、2、3 的列表对象；第二行 y = x，没有复制出第二张表，y 的箭头指向了同一个对象；第三行 y.append(4)，往这唯一的表里追加了一个 4；于是 print(x) 沿著 x 的箭头走过去，得到 1 2 3 4。争论了半天的歧义，在图上一目了然。

尽管名字里只有 Python，它支持的语言还包括 Java、C、C++ 与 JavaScript——郭说，这是如今教学与工业界最常用的几种语言。覆盖面大致是入门与中级编程课的内容：变量、对象、指针、数据结构与栈帧；同时也伸进系统课与编程语言课会遇到的一些进阶主题。它的目标从来不是教语法，而是模仿教师在黑板上做的事：帮新手建立关于代码如何运行的有用的心智模型。

规模是这场演讲反复出现的数字。按演讲简介的说法，二十年来，近三千万名学生与教师在 180 多个国家用它可视化了近十亿段代码。但现场幻灯片上的网站文案写的是另一组数字：自 2010 年以来，超过 2500 万人、180 多个国家、可视化超过 5 亿段代码，每天约有一万到两万人在使用。两组数字并不矛盾——前者是演讲时的最新口径，后者是网站上尚未更新的旧文案——但出入本身值得留意：这个项目的公开数字，始终带着一点手工维护的粗糙感。

比数字更让郭在意的是用户是谁。这不只是一群十八到二十二岁的大学生：南美洲一位五十岁的机械师，在免费公共自助终端上学编程，想转行做网站开发；一位网络工程师，通过芬兰主办的慕课进修，想让技能跟上时代；中东一位教师，在专为自闭症谱系成年人开设的非营利编程营里教课。这些故事没有经过独立核实，都是郭从用户来信里攒下的，但它们说明了为什么这个项目能搭上在线学习的浪潮——免费资源的需求，来自所有年龄与背景的人。

■ 心智模型（Mental Model）：新手头脑中关于代码如何运行的图景；教师的工作，就是帮他们建立有用的心智模型。

■ 程序可视化（Program Visualization）：把代码执行过程画成图的做法；索尔瓦等人 2013 年的综述所梳理的正是这一传统。

3. 第一幕 · 初创：四天做出的第一版

故事要回到千禧年之交。2000 年，郭在高中上 AP 计算机科学课，第一次爱上编程，教室里还是巨大的 CRT 显示器；高三那年，他成了这门课的助教，第一次体验帮学生理解代码。大学读计算机专业，又做了几年本科助教；2005 年大学毕业，同年秋天走进斯坦福盖茨楼读博士。幻灯片上有一张按年份排列的士气曲线，表情符号随著年份起伏：读博之后曲线跌破了横轴——孤立、拖延，配图是他坐在空荡荡的房间里、身边的地板上放著一台笔记本电脑，连家具都没有。

低谷里他学会了 Python 与 JavaScript，在个人网站上做些小项目。那正是 Web 2.0 的年代，人人都在尝试把东西搬上网。2008 年，读博第二年，他收到一封来自山景城一家创业公司的邮件：请他去给公司的科学家做 Python 培训。他没有教 Python 的经验，但还是去了，每周一次，教了三个月，边教边在黑板上画图——那些笔记，他上个月刚从壁橱里翻出来。教完他就把这事忘了，只当是众多副业中的又一个。

转折发生在 2010 年前后。他意识到浏览器已经好到可以自动画出这类代码图了——2008 年 Chrome 发布之后，浏览器竞赛让网页能力突飞猛进。他在一张纸上写下愿景，措辞与今天网站上的自我介绍惊人地相似：做一个基于网页的交互式学习平台，学生输入代码，单步执行，看数据结构如何随著执行而变化。然后他用四天时间做出了第一版：极其简单，连箭头都还没有画；没有域名，挂在学校某台服务器上；群发了几封邮件给朋友，就回去写博士论文了。

别人看到这个东西的常见反应是：这主意如此显而易见，怎么以前没人做过？几年后他才知道答案：其实有人做过。索尔瓦、卡拉维尔塔与马尔米 2013 年发表在《ACM 计算教育汇刊》的综述梳理了过去三十年里数十个程序可视化系统——这个领域的研究者对此并不陌生。问题在于，这些系统几乎全是短命的研究原型：桌面应用，要安装；做出来是为了发论文、做实验，评估一结束就被丢弃。没有一个真正走进日常教学。

“This is such an obvious idea—so why hasn’t it been done before?”这主意如此显而易见，怎么以前没人做过？

郭的解释是，他恰好是个外行。既有路线的系统由教授发起、走正式流程：写基金申请、招学生团队、定开发计划、跑对照实验，目标是证明新颖性，才能发表。而他没有任何这一套：没有基金，没有团队，没有发表压力，驱动设计的只有一条——做得尽可能简单、尽可能显而易见。更关键的是载体：前人做的是桌面应用，他直接做了网站。在当时，网站上的东西还不被当作"真正的应用"，更像玩具；可也正因为是网站，它没有任何安装门槛。创新者窘境里那句老话在这里应验了：下一个大东西，起初看起来总像个玩具。

■ 创新者的窘境（Innovator’s Dilemma）：新技术起初看起来像玩具，因而被既有玩家忽视；郭认为 Python Tutor 正是这样一个例子。

■ 别名（Aliasing）：两个变量指向同一份数据；y = x 之后改 y，也会改 x——开场小测验的核心。

4. 第二幕 · 加速：慕课大潮与"先把东西做好"

2012 年，郭博士毕业，Python Tutor 只有三个用户——三位教授，或从网上找到他，或是熟人，热心地用它教课，并与他通邮件交流。项目能不能继续下去，成了最现实的问题。他认真想过几条路：进公司，尤其是教育科技公司——副业经历有助于被录用，但进了大公司就得做主线产品；自己创业或做非营利组织——可这东西更像一个功能而非一个产品，要撑起一家机构，得像可汗学院那样搭起一整套生态系统；做教学型教授——他认为这条路与教育工具最契合，许多做类似项目的人都在这个位置上；最后他选了研究型终身教职，一边带研究组、教书，一边在缝隙里维护这个项目。

运气站在他这边。2012 年被称为"慕课之年"，大规模开放在线课程成了新闻头条；"人人学编程"的运动得到科技行业乃至政府的推动，大学计算机系也在扩招；十年后疫情又带来一波在线学习高峰。整个 2010 年代，Python Tutor 乘著这股浪往上走。但郭提醒听众：同一时期冒出来的在线教育应用与创业公司，绝大多数都消失了——登上新闻、拿一轮融资、然后无声无息。把时间线拉长，今天生成式 AI 的热潮与当年的情形几乎一模一样，只是换了词。

那么它凭什么活下来？郭的答案朴素到近乎玩笑：第一步，先把东西做好；第二步，画出猫头鹰的其余部分——这是网上流传的一幅梗图：先画两个圆，再画出整只猫头鹰，中间省略了全部关键步骤。他的意思是，做好本身没有捷径，但做好之后的事情是可以说清楚的。新用户的旅程是这样的：网上看到一个链接，点进去，一张图弹出来，"哦，这挺不错"；再试一下，"哇，它真的能用"；然后把链接分享给别人。点开即用：没有安装，没有账号，没有登录，几秒钟出图；覆盖的语言特性准确，图的抽象层次为学习而设，失败时也以可预期的方式失败。链接本身极轻，可以贴进任何聊天、论坛与文档；教师还能以 iframe 把它嵌进自己的网站。

嵌入带来的增长最出乎意料。一家中文算法与面试准备网站 hello-algo.com 把 Python Tutor 的可视化嵌进了自己的"快速排序"等章节，读者边读边看代码执行——郭很久之后才知道这个网站的存在，因为任何人都可以不经他许可就嵌入它。这股来自中国的流量成了网站流量的重要来源。用他幻灯片上的话说：别人的受众，变成了他的受众。

“You can’t buy love.”喜爱是买不来的。

与之对照的是那些自上而下、资金雄厚、公关齐全的教育科技项目：发布会、媒体通稿、宏大叙事，然后迅速消失。郭的判断是：人们不会因为东西看起来酷就用它、分享它；只有当他们心里冒出"哇，这东西真好"的直觉，才会真正用起来、传给朋友。他展示了自己发出的第一封推广邮件的回信，以及几年后有人把它贴到 Hacker News 后，评论区清一色的反应："这正是我一直在找的东西"、"我上的网课就该内置这个"。喜爱买不来，只能挣来。

■ 慕课（MOOC）：大规模开放在线课程；2012 年被称为"慕课之年"，Python Tutor 的增长正搭上这股浪潮。

■ 嵌入（Embed）：把可视化以 iframe 嵌进别人的网页；hello-algo 等站借此把自己的读者变成了 Python Tutor 的用户。

5. 手艺：软件的第四种做法

为什么是"挣"而不是"买"？郭把答案归于一种老派的心态：手艺。读博期间拖延的时候，他读了很多关于动手做东西的书，幻灯片上并排摆著其中两本：马修·克劳福德的《Shop Class as Soulcraft》，讲体力劳动的价值；罗恩·伯杰的《An Ethic of Excellence》，讲与学生一起建立手艺文化。幻灯片下方的字幕是：以关怀手艺赢得喜爱。

他把"做软件"分成四种：做产品，追求指标增长——卖钱，或者免费换取用户量与影响力；做研究，追求发现与发表——软件只是原型与实验基建；做艺术，追求自我表达——不在乎多少人用；以及做手艺——既要好，也要有用。郭说，自己属于最后一种：手艺与艺术的区别在于，手艺做的东西必须对别人有用；而也正因为有用、好用，才能挣来用户发自内心的喜爱。

手艺在实践中体现为抠细节。他展示了一封用户邮件：有人写 C 代码时遇到一段无法完整可视化的情形，写信来报告；他记下来、修掉，对方回信说"只是个小细节，没关系"；他回信说，细节很重要。正是成千上万个这样的小修补累积起来，让工具在复杂情形下也能按预期工作，让人打开它时觉得"这就是我想要的样子"，然后忘了它的存在。用他的话说，单个修补微不足道，加起来就是"它就是能用"的体验。

“People will fall in love with good things and tell their friends about it.”人们会爱上好东西，并告诉朋友。

这份手艺也得到了学术界的承认：总结 Python Tutor 设计原则的论文获得 2021 年 UIST 最佳论文；该项目还获得了 ACM SIGCSE 的长期影响奖；按 2021 年那篇论文的统计，它当时已促成 35 个研究小组的 55 篇论文。郭没有在台上罗列这些荣誉——以上数字来自斯坦福研讨会简介与论文本身，演讲正文只一笔带过。他更愿意谈的，是手艺心态如何帮他抵御了增长的诱惑。

■ 手艺（Craft）：既好又有用——郭自认的软件制作方式，区别于追求指标的产品、追求发表的研究与追求表达的艺术。

6. 增长会毁掉好东西：你在取悦谁

增长是好事吗？郭的回答是：增长可以毁掉一个好东西。项目一旦变大，就再也藏不住了，必须与所在组织的价值对齐：大公司里是对齐收入与版图，创业公司与非营利组织里是对齐变现与下一轮融资，教学岗位上是把一个简单想法扩成一整套课程乃至教学哲学，研究岗位上则是牺牲系统本身去换研究价值——加功能、改范围、收集数据。每一处对齐都在悄悄改写产品的形状。

他把问题推向更尖锐的一步：你到底在取悦谁？在大公司，真正要取悦的是老板与高管，升职与团队曝光才是项目方向的实际决定者；在创业公司与非营利组织，是资方与记者，好看的故事比守住核心更重要；在教学岗位，是同行与实践社群；在研究岗位，是审阅论文与基金申请的同行。这些取悦对象都不是用户。取悦非用户的人，最终会把项目拖垮——东西起初是好的，越往后越坏，因为不断有东西被堆上去。郭在这里借用了科里·多克托罗对平台由好变坏的论述。

他的抵抗办法只有一句：盯住用户与使命。符合使命的事就做：支持更多语言，让更多进阶结构可视化——他展示了一段嵌在文章里的 C 语言指针与数组示例，说明这些工作都服务于"帮新手建立心智模型"。不符合使命的事，哪怕再多人要，也说不：不做成完整的集成开发环境，不做生产代码的可视化与大规模调试器，不加学习管理系统、账号、进度、测验与评分，不亲自编写课程内容。这些都是好主意，只是不属于这个项目。

“Who are you really trying to impress?”你到底在取悦谁？

郭坦言，这份清醒很大程度上是被逼出来的。整个十年里，他首先是一名学者：带研究组、教书、指导学生，Python Tutor 只是他一个人在缝隙里维护的副业。正因为没时间，他不得不排序、不得不拒绝。约束逼出了清晰——这句话他说了两遍，一次是对听众，一次更像是对自己。

■ 平台劣化（Enshittification）：科里·多克托罗用来描述平台由好变坏的说法；郭借用这一论述，说明取悦非用户会如何侵蚀一个项目。

7. 第三幕 · 颠覆：AI 来了，用户曲线掉头

第三幕的标题页写著"颠覆（2023 年至今）"。郭展示了一张按月统计的用户曲线：漫长的上升之后，曲线在生成式 AI 出现前后见顶回落。他半开玩笑地说，不知道下滑有多少要归咎于 AI，但这会是他要讲的故事版本。字幕在此处有些含糊，年份听辨不清，谨慎的说法是：拐点出现在 2022 年底前后，与生成式 AI 进入公众视野的时间大致重合。

冲击是多方面的。公司以 AI 为由裁减软件岗位，大学计算机专业的入学人数开始持平甚至下滑；与此同时，AI 生成的克隆网站与搜索优化垃圾正在淹没网络——大量页面只是别家网站的空壳，套著广告，根本不能用。更直接的打击来自自家门前：他已经许多年没有更新网站界面了。用户调查的反馈毫不客气：印度用户说界面"看起来很旧"，美国用户说"美学需要改进，看起来过时了"，德国用户说前端"不是为年轻一代设计的，白底加笨重感"，巴基斯坦用户说工具极有帮助，但界面"有点过时，有时让新手困惑"。这些引文与日期都印在幻灯片上，来自 2025 年 8 月至 12 月的调查。

他的回应不是追赶潮流，而是重新定义成功。第一，接受用户基数可能缩小的新现实，把成功从数字的增长改写为参与的深度——曲线上扬固然好看，但它到底意味著什么？第二，把重心从学习者转向教师：教师人数少得多，但参与得深得多；他展示了几位从 2011、2012、2013 年就一直用下来的老用户。第三，押注 K–12：大学计算机教育在降温，但中小学阶段一直在升温，而且一旦课程标准与政策落地，就会非常"黏"——AP 计算机科学的课程大纲多年未变，正如中小学数学教的内容与一百年前大同小异，基础性的东西一旦扎根就很难被拔掉。

界面翻新也在进行，但他刻意没有交给 AI 去"现代化"——那样只会让它看起来像其他所有用 AI 做的网站。他很幸运地找到了一位有才华的视觉艺术家与设计师合作（演讲中没有提及她的姓名），由两人共同定下整体审美，再由 AI 负责实现：首页、那张实时地图，都是这样做出来的。合作的感觉很好，他说，"方向盘仍然握在我们手里"。

这种分工也延伸到了后端。郭形容自己如今像在"监管一支 AI 团队"：程序员、测试员、数据科学家、IT 与安全专家——全是 AI 扮演的角色。他的工作变成了产品经理：拆任务、派活、检查、把关。这让他感到振奋，也让他第一次认真面对房间里的大象：如果 AI 会替我们写全部代码，为什么还要用 Python Tutor？为什么还要一步一步学代码如何运行？

8. 尾声：为什么还要学代码如何运行

这是他如今被问得最多的问题。他的回答先搬出计算机教育界的共识：AI 没有让学习变得过时。哪怕专家天天用 AI 写代码，新手仍然要学基础——计算思维与解决问题的能力——因为只有这样，他们才能成为会用 AI 的专家。他举了数学的例子：牛津至今仍在白板上一步一步教数学，尽管计算器与计算机早已存在；数学课教的从来不只是算出答案，而是把思考过程想清楚。编程也一样。

再往深处说，Python Tutor 的使命从来不是教人写课堂上的小程序，而是让人理解、调试并接手别人写的代码——如今也要加上 AI 写的代码。如果 AI 在写我们的大部分代码，我们仍然想办法去理解它、调试它、掌控它，仍然想坐在方向盘后面。这番话说完，他话锋一转，承认了自己的处境：这正是既得利益者的想法。当年在读博时他是局外人，如今他坐在一个拥有庞大用户群与整个领域背书的系统之上——这让他恰恰最容易受到颠覆。

“If AI is writing most of our code, we still want to be able somehow to understand and debug it.”即使 AI 在写我们的大部分代码，我们仍然想办法去理解它、调试它。

为了把这种自我怀疑讲透，他花了不少时间做了一段 AI 生成的《泰坦尼克号》小品：教育界的掌舵者们戴著高礼帽，自信满满地宣布"学习计算思维的基础将永远重要"；与此同时，教育之船正在开裂，所有人纷纷落水；落水者还在喊"永远重要"；最后他扮演杰克，对萝丝说"答应我，告诉所有人，学基础永远重要……我永远不放手"。他承认这段花了太多时间，本该用来准备演讲——但笑声过后，意思很清楚：把一句正确的道理重复得越自信，离现实可能越远。

希望的微光来自两处。一是他在 Notion 的一场 AI 工程会议上听到一位同行说：即便天天用 AI，理解事物如何运作仍然重要；近一年来，公众的风向似乎在变——炒作过后的反弹里，"真正把东西搞懂"正在变成一种新的身份象征；更年轻的一代从小看著内容过载长大，反而开始渴望深度与真实。二是他相信人们分得清东西是不是"为人而做"：当 AI 批量生产出超工业化、超优化、快餐式的软件时，手工的、有温度的东西反而会被认出来——不一定最能扩张，不一定最受关注，但它能给人满足感。

演讲的最后一张幻灯片回到起点：左边是 2008 年的手写笔记，右边是 2009 年那张没有家具的旧照，下方一句话："把东西做好，并一直做好，就会带来长期的满足感。"郭说，这既是手艺的使命，也是相当自私的动机——做一件好东西、让它长久地好下去，本身就是他二十年来满足感的来源。

8.1 问答精选

问答环节从一位如今在斯坦福读博士的学生开始：他中学时就用 Python Tutor，觉得自己的计算机教育要归功于它。他问郭在博士与教授期间花了多少时间、如何平衡。郭的回答很实在：利用缝隙，一阵一阵地做——没有论文截止日期、没有教学任务的几周，就集中做一阵；不需要在任何一个时间点投入很多时间，能持续二十年，恰恰因为它可以这样断断续续地做。

有人问会不会支持 K–12 的 MakeCode 与 micro:bit 这类实体计算。郭说这是很好的方向，他与微软的一位相关人士聊过（字幕中姓名听辨不清），希望借助 AI 工具让这类一步一步的可视化也成为可能。还有人问到一项关于心智模型的研究：做过前测的班级里，心智模型最连贯的学生成绩最好——那能否用 Python Tutor 积累的日志做研究？郭的回答点出了设计的代价：他刻意没有给网站加账号与追踪，日志因此非常嘈杂；想做研究的人可以自己在上面加仪器，但"收集更好的数据"与"保持简单的体验"之间存在根本冲突。

最后两个问题都很"大"。有没有可能建立某种社会组织或学术机制，来保护这种"不必取悦各方、只忠于愿景"的做事方式？郭说他想了许多年，现场没有答案；最接近的类比是加入那些有前瞻性的组织，待上一阵，等风向变了再换地方——早期的 OpenAI、谷歌与微软内部的一些角落都曾是这样的地方，而学术界因为教学与大学的稳定性，可能是最长久的一种。另一位提问者问：为什么偏偏是你的项目火了？郭的回答不太令人满意，但很诚实：问题本身选得合适——人人都在手绘代码图，这事"就在空气里"；再加上门槛低得几乎没有，于是它就火了。至于当年做副业时有没有期待其中一个会成功？没有。他说自己对赚钱与创业有种"过敏"——在斯坦福读博时，人人谈副业都是为了创办公司，只有他只想做东西本身；读博期间的奖学金让他没有后顾之忧，惯性也帮了忙。纯粹的动机，用他最后的词说，是自我实现。

■ 第二代用户（Second-Generation Users）：当年做学生时用过 Python Tutor，如今做教授或教师后又拿它教学生的人。

9. 讨论问题

1. 如果"先把东西做好"是第一步，第二步"画出猫头鹰的其余部分"在你的项目里具体指什么？有哪些细节值得你花一个下午去修？

2. 郭把做软件分成产品、研究、艺术、手艺四种。你的工作属于哪一种？如果换一种，哪些取舍会立刻改变？

3. "你到底在取悦谁"——列出你的项目真正的用户，和那些"非用户"的评审者；最近一次为后者改设计是什么时候？
