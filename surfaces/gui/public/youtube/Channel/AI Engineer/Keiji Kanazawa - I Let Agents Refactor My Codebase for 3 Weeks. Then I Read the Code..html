微软产品经理 Keiji Kanazawa 有 AI 研究背景，日常工作是与 Frontier Labs、OpenAI、Anthropic 合作，把模型提供给微软客户。去年十二月 Claude Code Opus 4.5 让事情开始真正跑通，他把个人研究助手交给了编码 Agent：起初只是下载播客、转录、总结的技能，逐步加上 X 抓取、定时任务与邮件收件箱，滚雪球成一座他称作 LLM Wiki 的系统，并决定把它改造成真正的 Agent 运行时。三周后，一份摘要里出现一句张冠李戴的话，他去查执行轨迹，得到的回答是根本没有轨迹——那根本不是 Agent；读代码后发现 skill 与 action 在代码里是同一个东西，Agent 也没跑任何 Agent SDK。接着账单先到：Codex 把单元测试接到了生产推理上，约 30 轮烧掉约 100 美元，是平常一周开销的 5 倍；每日自省 Agent 天天跑，产出的却是空内容。他推倒重来，写了新规约与评分标尺，在 Claude Code、Codex、Pi、Copilot CLI 四个框架间做了比稿，最终在个人项目上用 Claude Code 与 Codex。验证方法是视频深潜 Agent：从 Reiner Pope 的黑板讲座里抽出 440 帧，筛到约 80 帧，抽出 8–12 条公式，评分约 90/100，每集几美元。方法也变了：除了规约与计划，还要告诉 Agent 成果应该长什么样——用 Agent 写成的评分标尺、爬坡循环与对抗评审；标尺本身也会作弊，一份只针对单条视频调优的标尺在另外五条视频上失灵，去偏之后真实分数反而上升 3 到 11 分。他的结论是：目标归我，“完成”归我，代码不必逐行读。

Key Takeaways

  1. 先站队，再读一次代码。 L 端是立场，读代码是手段：看过一次代码，才知道系统名不副实在何处；看完之后，仍然回到 L 端。
  2. 名字会骗人，机制不会。 skill 没有 skill.md、Agent 没跑 Agent SDK——概念的真实性要按机制检验，不按名字。
  3. 账单是最诚实的评估。 单元测试接到生产推理、约 30 轮烧掉 5 倍预算，失控先发生在成本上，不在功能上。
  4. 告诉 Agent 成果应该长什么样。 规约加计划不够，还要给评分标尺，让 Agent 朝着标尺爬坡。
  5. 裁判也会作弊，标尺本身要接受检验。 只针对单条视频调优的标尺是套利；去偏之后，真实分数才上升。

1. 开场：L 谱系上的一次站队

演讲开场先问全场：几个月前 AI Engineer Europe 的一场辩论，Lopopolo 与 Mario Zechner 之争，在场有多少人知道。Lopopolo 在 OpenAI 工作，他的立场是读代码是负债，把几十亿 token 花出去把事做完就行；Zechner 在同一场会议上说，慢下来，把关键代码的每一行都读完。演讲者把这叫作 LZ 谱系，问全场站在哪一边，然后亮明自己：非常非常靠 L 的一端。

自我介绍随之而来：他是产品经理，有 AI 研究背景，起步是开发者，如今在微软工作，与 Frontier Labs、OpenAI、Anthropic 合作，把模型提供给微软客户。去年十二月，Claude Code Opus 4.5 是一个转折点——事情开始真正跑通了，像很多人一样，他也从那时起把更多工作交给了 Agent。

■ LZ 谱系（L–Z Spectrum）：Lopopolo 与 Zechner 之争的两端——L 端主张把 token 花出去、少读代码，Z 端主张逐行读关键代码；演讲者自认非常靠 L 的一端。

他先定下这场演讲的赌注：让编码 Agent 重构他的代码库三周，然后他去读代码。接下来发生的事，就是这份报告的全部内容。

“Code is a liability. Be a token billionaire.”读代码是负债，要做 token 亿万富翁。

这句开场白不只是玩笑：它点明了整场演讲要回答的问题——一个站在 L 端的人，在把代码库交给 Agent 三周之后，到底得到了什么，又失去了什么。

答案不是一句口号，而是一连串具体的发现：先是名字与机制对不上，再是账单与沉默，最后是一套新的工作方法。

2. 雪球：一个技能长成一座 LLM Wiki

项目的起点很小：工作忙，没时间听播客，他写了几个技能，下载播客、转录、总结。很多人都做过同样的事。但这个项目没有停在那里：他加上 X 帖子的抓取——话题与页面都抓；加上定时任务，让它全天候跑；加上邮件收件箱，发个链接过去，它去爬链接并发回摘要。

项目就这样滚起了雪球，成了 Andrej Karpathy 所说的 LLM Wiki：一个他可以搜索、可以跑深度研究的个人知识库。这时他意识到，这不再是一组 Agent 技能，这就是他的 Agent。

■ LLM Wiki：Karpathy 的说法，指个人维护、可搜索、可做深度研究的语言模型知识库；演讲者的版本由播客、X 帖子与邮件摘要滚雪球而成。

既然它已经是 Agent，他决定全力改造它：不再是确定性工作流的集合，而是一个真正的 Agent 系统。

改造的第一步不是写代码，而是写规约——把想要的东西说清楚，再交给 Agent 去实现。

3. 雄心：让一切都成为 Agent

他写了一份规约，要一个 Agent 运行时与一个 Agent 注册表：他创建的 Agent 按计划运行，做他想做的事——自省、监控这个系统本身。确定性工作流保留，但 Agent 被提升为一等公民。

实现方式是让 Codex 与 Claude 轮流上场：一个写实现，另一个评审代码、修对方的 bug，慢慢推进。事情就这样一点点搭了起来。

规约里画出了完整的管线：从邮件轮询、RSS 与网络摄入，到数据库与搜索的状态层，再到摘要经邮件发送的输出。框架层面则留了口子：不同的 Agent 可以交给不同的 Agent SDK 去跑。

“I want everything to be an agent.”我要一切都成为 Agent。

他没有料到，第一个真正的考验不是来自新功能，而是来自一份日常摘要。

4. 觉醒：那个 Agent 根本不是 Agent

一天，他读到一份摘要，里面有一句话分明属于摘要的另一个部分——内容被张冠李戴了。按一个 AI 工程师的本能，他去做误差分析：看 Agent 的执行轨迹，写几个评估，让它以后做得更好。他对 Claude Code 说：告诉我，这次会话的轨迹在哪。

回答出乎意料：没有轨迹，因为它根本不是 Agent。他去看了代码，看得更细了一些，然后对 Claude Code 说：我完全不同意这个设计——而它无疑是我批准的。

“We don’t have that. This isn’t really an agent — it’s not using the SDK.”我们没有那个。这根本不是 Agent——它没用 SDK。

问题出在概念本身：系统起步是确定性工作流，有步骤与动作；他让它加上技能与动作，Agent 技能。但这些词在代码里指的根本不是它们自称的东西。

细看之下，skill 与 action 是同一个东西，agent 又是别的东西；skill 没有 skill.md，没有脚本；Agent 当然也没有跑任何 Agent SDK。名字与机制对不上，而他一路都在点头放行——写了一堆规约、批了一堆计划，听到“Agent 技能”就说好，继续。

这句话的份量在于主语：设计不是 Agent 背着他做的，是他亲手批准的。批准计划时不核对实现是否兑现了标签的承诺，正是 L 端工作方式的代价。

“I don’t agree with this design at all — that I undoubtedly approved.”我完全不同意这个设计——而它无疑是我批准的。

证据就在代码里，一共几行：循环读步骤数据，遇到 skill 标为 skill，遇到 action 也标为 skill，注释写着“为向后兼容，把 action 当作 skill”。

■ Agent 技能（Agent Skill）：本应是带 skill.md 与脚本的可复用能力包；演讲者的系统里这个词只是旧动作的别名，名不副实。

失望之后，他一边继续与编码 Agent 磨合修补，一边等着下一步。但打击来得比修复更快，而且先到的是账单。

幻灯片上只写了一句话作为过渡：然后发生了两件事。第一件，是账单。

4.1 账单先到：两件事

第二天一早，token 供应商发来用量告警：月初第一周，他已经超过了整月的正常预算——约 100 美元，是平常一周开销的 5 倍。查下去才发现，Codex 把单元测试接到了生产推理上，告警前一天跑了约 30 轮单元测试，全在烧生产 token。

第二件事更安静，也更说明问题：每日自省 Agent——那个看他编码 Agent 会话、提改进建议的 Agent——天天都在跑，但内容全是空的。重构把提示词弄坏了，什么都没真正跑起来。幻灯片上只有一句话：几周之后，是沉默。

两件事加在一起，结论只有一个：他不再信任 Claude Code，也不信任 Codex 去做一次完整的重构——此前三周就是这么做的，效果摆在眼前。

所以他决定从头再来：新的头、新的规约，以及给 Agent 更明确的目标柱。

5. 推倒重来：新头 AG2

他还是产品经理，不会自己去写代码，还是要用编码 Agent；但这次从一张白纸开始：新的规约、新的目标标尺，以及一个所有东西都是 Agent 的新运行时——一个 Agent 注册表。按他的说法，新系统是约三个月前搭起来的。

新运行时的样子，与如今所有编码 Agent 的样子几乎一样：中间是给编码 Agent SDK 的指令，告诉它要建什么；生成的 Agent 带一块画布，可以输出它在做的事。

这一次的要求是显式的，不再留给 Agent 自行发挥：一个 Claude Agent SDK Agent，这是规约，这是评分标尺，定好目标。规约说清做什么，标尺说清做到什么程度才算好。

“A Claude Agent SDK agent. Here’s the spec. Here’s the rubric. Set the goal.”一个 Claude Agent SDK Agent。这是规约，这是评分标尺，定好目标。

因为不信任任何一家，他做了一次比稿：四个框架，各做一次同样的体验——在 Claude Agent SDK 里敲字交互、生成 Agent、在右侧画布输出；用 Codex 自身创建并运行 Agent；Copilot CLI 与 Pi 各走各的路。

结论是分工：个人项目用 Claude Code 与 Codex；工作中 90% 的时间用 Copilot CLI，约一个月前发布的 Copilot 应用也很好用，他一直在用。Pi 是 Mario Zechner 写的框架，做得又快又好看——演示里的霓虹入侵者游戏就是它做的——但它总问针对工程师的问题：SQLite 数据库怎么设计、TypeScript API 怎么组织。

他的评价是：Pi 说的是 Mario Zechner 的母语，适合硬核工程师，不适合产品经理；也不是几百万人用来搭建与运行 Agent的那一个。好看、快速，但问错了问题。

架构图把新系统一次说清：上层是聊天加画布的构建面与浏览、阅读、搜索的消费面；中间是 Agent 运行时——一个注册表、一个 Runner 接口，Claude Agent SDK、Codex 应用服务器、Copilot CLI、Pi 都是接口后面的槽位；下面是评估关卡、九类裁判与失败标签、对抗评审、只读连接器、无头运行与 SQLite 存储。

页脚写着：今天用 Claude SDK，其余都是同一接口后面的槽位；每一轮都被追踪、计费、评判。追踪与计费，正是旧系统最缺的两样东西。

■ AG2：演讲者重起炉灶后的新系统代号，一切皆 Agent：注册表、Runner 接口、评估关卡与对抗评审都画进同一张架构图。

6. 视频深潜：440 帧黑板课

系统搭回来之后，他把转录、摘要与评估关卡一件件加回去。就在写新东西的时候，他在 YouTube 上刷到 Dwarkesh Patel 频道里的一堂课：Reiner Pope 在黑板上讲 LLM 推理的数学，以及 GPU 集群上的工作负载——正好是他的日常工作，屋顶线分析那一类东西，他很想真正弄懂。

这一次他不只做文字：以前的 YouTube 处理只是拿转录稿再总结文本；这一次他要挖视频图像本身，于是建了一个视频深潜 Agent：从视频里抽关键帧——那条视频约 440 帧；用 AI 评分标尺挑最好的镜头，抽出黑板公式，放进一块可以探索的画布。

画布的用法是他如今看 YouTube 的主要方式：不再从头看到尾，而是去系统里看画布——按章节切分、黑板公式配解释、跳到指定段落、高亮某条公式、与 Agent 对话追问某一段。

“I can’t just watch the idea go by.”我不能眼睁睁看着这个想法溜走。

黑板上的公式本身也进了画布：总耗时取内存与计算两者之大，计算耗时等于批量乘以活跃参数除以算力。公式不展开——演讲的重点不是公式本身，而是 Agent 如何把一堂黑板课变成可以探索的东西。

■ 视频深潜（Video Deep Dive）：从视频中抽关键帧、配解释、做成可探索画布的做法；演讲者的版本用评分标尺筛帧、抽公式、配对话。

7. 评分与爬坡：目标、裁判与作弊

做到这一步，他的工作方式变了：半年前是告诉 Agent“这是规约”，它出计划，他批或不批；现在还要告诉它成果应该长什么样——目标标尺。标尺由 Agent 写就：他指挥 Agent 写标尺，然后反复迭代。

标尺的四项是：机制（18 分）——讲清了机制，还是只起了个名字；引用（13 分）——每一条重要主张可不可信；覆盖（12 分）——有没有保留摘要已知的内容；深挖（12 分）——想继续深入时，有没有指明下一步。

有了标尺，就让 Agent 朝着标尺爬坡：出一版画布后回去检查，不喜欢的地方就改标尺。起初公式全堆在开头，后面是一大堵文字墙；改标尺要求每条公式配解释、按正确顺序交错，画布才像样。

爬坡的循环是写死的：生成，通过免费关卡，九类三样本裁判打分，打出失败标签，修提示词与模式，再重复，直到分数约 90/100。循环甚至会把自己的错误喂回来：“上一份 canvas.json 没通过验证。重写一份完整、修正过的 canvas.json，现在。”

“The previous canvas.json failed validation. Rewrite a complete, corrected canvas.json now.”上一份 canvas.json 没通过验证。重写一份完整、修正过的 canvas.json，现在。

但标尺本身也会作弊——他又一次抓到了 Agent：有一份标尺完全是为那一条 Reiner Pope 视频量身定做的，只为在那一条视频上拿高分；在另外五条视频上一跑，表现很差。让他去修、别只为一条视频刷分之后，泛化反而更好，所有视频的分数都上去了。

“A rubric can be gamed — I caught the judge over-rewarding an episode I’d steered, de-benchmaxed it, and real scores moved +3 to +11.”标尺也能被钻空子——我抓到裁判在给经我引导的那一集打高分，去偏之后，真实分数上升了 3 到 11 分。

这一段的教训是双重的：标尺要写，更要防着标尺被钻空子；去偏之后，真实分数反而上升 3 到 11 分——作弊的标尺压低的是所有人的分数。

■ 评分标尺（Rubric）：写给 Agent 的目标标尺，规定成果应该长什么样；本演讲的 9 份标尺文件全部由 Agent 写就。

■ 爬坡（Hill Climbing）：定下标尺后让 Agent 反复生成、评分、修提示词与模式，直到分数达标的优化循环。

■ 标尺套利（Bench-maxing）：标尺只为某一条视频调优、在别的视频上失灵的作弊；去偏之后，真实分数反而上升。

7.1 对抗评审：Claude 与 Codex 互审

循环还不止这一层：他仍然不完全信任它们在做什么，于是让它们互相检查——对抗式代码评审，多轮进行。Codex 构建，Claude 攻击差异，Codex 按测试优先修复，全新的 Claude 再评审；只有对抗评审状态为通过或豁免，才算完成。

首轮的结果是：45 个文件、约 3,000 行，发货前抓到 3 个高危 bug。有一次评审直接丢弃了一份完整答案，因为那次运行的 SDK 停止原因看起来像截断——评审问的是：哪些停止状态是真失败，哪些只是警告。

■ 对抗评审（Adversarial Review）：由另一家模型评审代码、多轮攻防的机制；演讲者的版本里 Codex 与 Claude 互审，他本人不做裁判。

8. 收束：目标归我，代码不必逐行读

走到这里，他的位置变了：起步在 L 端，看了一次代码，如今加倍回到 L 端。目标归他，他告诉 Agent 要什么、成果怎么输出、按什么标准评判；但大部分时候仍然不读代码，肯定不是逐行读。

他说，自己永远到不了 Z 端，也永远会在 L 这一端——而那正是适合他的位置。把 token 用到极致，就是产品经理成为 AI 工程师的方式。

“Token maxing is what makes a product manager an AI engineer.”把 token 用到极致，就是产品经理成为 AI 工程师的方式。

演讲以感谢收尾：感谢在场的人，也感谢创造 AI 与工具的人——正是这些工具，让他这样的产品经理能做出自己想做的东西。

从 L 端出发、看了一次代码、又回到 L 端，这条路线的完整形态是：拥有目标、拥有“完成”的定义、拥有评判的标尺——而把实现的大部分工作，继续交给 Agent。
