拥有自己的 Agent 与 RL：微调正在从手艺变成工程

Training Your Own Agent Models With RL Is Now Practical

把模型当成随手可换的静态后端，是条输路——Modal 的 Jason Mancuso 在这场演讲里论证，竞争一旦发生在 Agent 经济学与体验上，赢面就在微调：它带来可靠的 SLO 与自有推理、预训练里没有的专有数据，以及按每美元任务智能竞争的差异化价值。SFT 之所以脆弱，是因为 Agent 的会话是一棵分叉的树，训练只见过一条录制轨迹，上线遇到的却是另一条分支；而 RL 在训练中探索全部分支，泛化才对得上 Agent 的形状。好消息是，上线部署本身就有 RL 的原料：脚手架加评估就是环境，生产轨迹挖出失败、合成任务，就是训练集。配方只有四块：GRPO 加掩码重要性采样、分数中心化与带掩码重放的 top-p 采样，修正的正是异步训练里的失配与漂移；在 Qwen3.6-35B-A3B 的代码 Agent 消融里，它比任何一种替代都稳。Modal 的容量模型来自 15 到 20 家供应商的聚合，算力碎片化使大集群难调度；但权重更新极度稀疏，压缩后通信量降到千分之一，推理 GPU 可以搬出集群、在异构硬件上跑，rollout 反而便宜约 15%。

Key Takeaways

  1. 换模型是条输路，微调才是护城河。模型是静态后端思维；竞争一旦发生在 Agent 经济学与体验上，赢面就在微调带来的自有推理、专有数据与差异化价值。
  2. SFT 脆弱，RL 才对得上 Agent 的形状。SFT 只在一条录制轨迹上训练，Agent 会话却是分叉的树；RL 在训练中探索分支，泛化更好。
  3. 上线部署本身就有 RL 的原料。脚手架加评估就是环境，生产轨迹挖失败、合成任务，就是训练集。
  4. 配方只有四块，关键在修正失配。GRPO 加掩码重要性采样、分数中心化、带掩码重放的 top-p 采样；失配与漂移不修正，异步训练就会失稳。
  5. 权重更新极度稀疏，推理可以搬出集群。更新量压缩千倍后，推理 GPU 不必与训练同处一集群；在异构硬件上跑，rollout 反而便宜约 15%。

1. 开场：别把模型当静态后端

演讲的开场先给听众画像：不少 AI 工程师把模型看作静态后端——新模型一出，测一测、跑跑评估、做做 A/B 测试，再把脚手架重构成最便宜、质量又最高的那个。模型 A、模型 B、模型 C 在脚手架下面轮换，哪个合算用哪个。

“A lot of AI engineers view models as static backends that they swap out as the new models come out.”不少 AI 工程师把模型看作静态后端，新模型一出就换掉。

演讲者的主张是，这条路一旦要同时竞争 Agent 经济学与 Agent 的体验，就会输。便宜与高质量之间没有免费的切换：每一次换模型都要重建脚手架、重跑评估、重新调校，而对手在你换模型的工夫里，已经把差异化做进了自己的模型。换模型省下的钱，抵不过在体验与成本两端同时落后的代价。

2. 为什么还要微调：三条理由

演讲者先回答一个前提问题：既然新模型一代比一代强，为什么还有人微调？他从 Modal 收到微调需求的客户那里归纳出三条理由。第一条最常见：部署需要可靠的 SLO，模型必须足够可靠地撑住线上服务；开源模型开箱即用的质量往往撑不住部署，质量退化不可避免——微调是拥有自己推理的唯一路径。

“Fine-tuning was the only path to owning your own inference.”微调是拥有自己推理的唯一路径。

第二条是专有数据：Agent 要推理、理解并行动的数据集根本不在任何预训练集里，开箱的 Claude、GPT 对这类任务完全行不通，除了微调开源模型别无选择。第三条正在兴起：为了做出差异化价值，越来越多团队选择在栈的每一层垂直整合；在编码这类按每美元任务智能竞争的行业最常见，而随着行业成熟，这股趋势会扩散到编码之外。

■ 微调（Fine-tuning）：在预训练模型的基础上，用特定任务的数据继续训练，使其适配部署需求的做法。

演讲者也承认怀疑的来源：最新模型一出来，总比上一代能微调出的任何模型都强。但他认为这三条理由不会消失，长期看微调只会更普遍——新模型变强，改变的是起点，不是这三条理由本身。

3. 为什么是 RL，而不是 SFT

微调分两种，SFT 与 RL，为什么这场演讲只讲 RL？SFT 是在生产中录制的轨迹上训练；问题在于 Agent 的会话按轮次展开，是一棵分叉的树。训练时走的是其中一条轨迹，上线后模型遇到的很可能是另一条从未见过的分支。

“SFT is quite brittle in this regard.”在这一点上，SFT 相当脆弱。

RL 的做法不同：模型在训练时就会探索这些分支——这正是人们说 RL 泛化更好时通常指的意思。演讲者没有把 RL 说成玄学：他把 RL 的优越性落在一个机制上，探索发生在训练时间，而不是部署之后。

■ 监督微调（SFT）：在生产录制的示范轨迹上训练模型的做法；轨迹之外的新分支不在训练分布内。

■ 强化学习（RL）：模型在环境中自己产生轨迹、按奖励信号更新的做法；训练时探索分支，泛化通常更好。

“In RL the model actually explores all of these branches during training time.”在 RL 里，模型在训练时真的会探索所有这些分支。

4. 上线就有 RL 的原料

接下来是演讲者要拆掉的第二道墙：RL 很难。他的反驳是，如果你已经有一个上线的 Agent 部署，你大概已经有了需要的原料。部署意味着两样东西：一个已经跑在生产环境的 Agent 脚手架，以及某种评估——不一定叫评估，A/B 测试、任何形式的变更管理都算。

“If you have an agent deployment in production, you probably already have the ingredients you need.”如果你已经有一个上线的 Agent 部署，你大概已经有了需要的原料。

这两样东西合起来，就是一个 RL 环境。脚手架提供交互的场所，评估提供判断好坏的标准。而训练任务从哪里来？最好的来源是生产轨迹本身：把用户真实在做的事情合成出任务，尤其要挖出失败的例子、围绕它们建任务，微调才有机会在那些地方真正改进产品。做到这一步，RL 的原料就齐了。

这里的关键转折是，环境不是要从零搭建的实验室，而是生产部署的复用。评估也不必是学术意义上的基准——只要能判断一次变更是变好还是变坏，它就能当奖励信号的来源。

5. RL 是怎么跑的：循环、顺序与异步

演讲者先把 RL 的机械结构讲清楚：循环里有两拨 GPU。推理 GPU 跑采样器，也就是正在训练的模型，在环境里用脚手架生成 rollout；rollout 被收集起来喂给训练器，训练器用梯度下降更新模型；更新后的权重再广播回所有采样器，下一批 rollout 就来自不断变好的模型。两边来回迭代，模型就是这样变好的。

■ 采样器（Sampler）：跑正在训练的模型、在环境里生成 rollout 的推理侧角色。

数学上，RL 偏好顺序执行：先采样，再训练，再把更新送回采样侧，让下一批 rollout 来自新版模型。但这样浪费大量空闲算力——采样时训练器在等，训练时采样器在等。GPU 可以在两边共享，但对 Agent 尤其好的做法，是让两边持续并行、异步进行：GPU 打包得满，利用率高，不浪费钱。

异步的代价随之而来。第一是陈旧性：rollout 很可能来自旧版模型——采样出自 V1，正在训练的已经是 V3，V1 的 rollout 对 V3 还有用吗？这正是异步 RL 过去不稳定的原因之一。

“Rollouts were generated by V1. The current model that you’re training is V3.”采样来自 V1，而你正在训练的模型已经是 V3。

第二个不稳定来源纯粹在系统层：栈的每一层都可能出现细微的行为差异，训练器以为自己在训的东西，与采样器以为自己在采的东西，并不完全相同。RL 的数学默认两边在同一分布上学习，实际却略有偏差。演讲者的解法不是消除这些差异——那做不到——而是用一组最简单的修正，把失配的影响控制住，又不淹没训练信号。

■ 陈旧性（Staleness）：异步 RL 里 rollout 由旧版模型生成、而训练对象已是新版模型的时间差；旧 rollout 对新模型的用处会打折。

6. 配方：GRPO 加三处修正

配方从 GRPO 起步。这是 DeepSeek 为 DeepSeek R1 引入的方法，此后成了语言模型 RL 的基石。GRPO 之上加三样东西。第一是掩码重要性采样，修正逐 token 的失配——失配不仅来自系统层的差异，也来自陈旧性：旧版模型在某个位置会采样出不同的 token，比值可能差得很远，必须以某种方式修正。

■ GRPO：群组相对策略优化，DeepSeek 为 DeepSeek R1 引入的 RL 方法，此后成为语言模型 RL 的基石做法。

■ 掩码重要性采样（MIS）：按逐 token 的重要性比值修正采样分布与训练分布之间失配的做法；同时覆盖系统差异与陈旧性。

第二是分数中心化。即便逐 token 的失配都修正了，残余的失配仍会在训练过程中累积，进到权重本身里——最新版模型与它本该成为的样子之间总有细微偏差。分数中心化是把这份随漂移累积的量建出来、再把它去掉，修正的不只是一步，而是一整段训练。

■ 分数中心化（Score Centering）：把训练中累积的漂移建项并加以去除的做法；修正整段训练的漂移，而不只是一步。

第三是带掩码重放的 top-p 采样。top-p 是采样参数，只考虑分布中累计概率排在前 p（0.95 或 0.98）的 token，砍掉一大批极罕见、很可能很差的 token。如果采样器只从这些 token 里采，训练器却不幸采到了一个罕见 token，质量失配可能是灾难性的，必须修正。而在分数中心化的数学里，配合 top-p 采样，这项修正从近似变成了精确——不用 top-p 时，它只能近似修正漂移。

■ top-p 采样（Top-p Sampling）：只从累计概率排在前 p 的 token 中采样的做法；砍掉极罕见的坏 token，但采样侧与训练侧的质量失配必须修正。

三样东西加在一起，训练变得稳定得多。演讲者没有展开每项机制的数学细节，而是指向了论文：GRPO、掩码重要性采样、分数中心化与 top-p 掩码重放各有出处，连同 IMPALA 与一篇 LMSYS 博客，构成了这张“科学并不难”的清单。

6.1 消融：Qwen3.6-35B-A3B 上的验证

配方行不行，要看消融。实验是在 Qwen3.6-35B-A3B 这个 MoE 模型上做的，在代码环境里训练，以 pass@4 在 HARD-51 子集与全集上评估。图里同时跑了多种组合：只用 GRPO、GRPO 加掩码重要性采样、GRPO 加 top-p、只加分数中心化、分数中心化加掩码重要性采样，以及三者全加。

结果是全配方最稳。HARD-51 上，全配方的 pass@4 从约 50% 爬到约 75%，全集上稳定在约 95% 附近；而几种替代组合有的中途崩到接近零，有的在 200 步训练里始终落后。演讲者的结论是：三处修正合起来，比任何一种单独使用都稳定得多。

这张图的另一个信息在图例里：实线与虚线区分的是采样器的构成，混合采样器与同构采样器——这正是下一节的伏笔：配方要扛住的失配，不只来自算法，也来自硬件本身。

7. 为什么是 Modal：容量模型逼出了解耦

配方讲完，演讲者才谈 Modal 本身。Modal 做训练，集群功能刚 GA；也做推理，有大量端点，在规模化 LLM 推理上做了很多硬活；RL 需要的环境跑在 Modal 沙箱里。单看这些，Modal 似乎天然就是一块做 Agent RL 的料。

但 Modal 的容量模型与别人不同：它聚合了 15 到 20 家供应商的算力，既有超大规模云厂商，也有 Neo Cloud，并负责 GPU 健康与可靠性。这带来可靠、灵活的调度，绕开算力短缺；但也把算力池切碎了。调度 4 节点、8 节点的集群还算快，一旦到 16 节点、32 节点，要找一整块连续的节点就很痛苦、很耗时。

这在 RL 里尤其糟：Agent RL 通常是两个推理 GPU 配一个训练 GPU，集群里三分之二的算力其实只在做推理。8 节点集群里，训练器只占两三个节点，其余全是推理。如果能把推理 GPU 移出集群，问题就小得多。

7.1 权重更新极度稀疏

能移出去，是因为权重更新本身极度稀疏。把第 T+1 步的模型减去第 T 步，得到的差值里绝大多数是零——完整权重又密又大，更新却比它稀疏 100 倍甚至 1000 倍。喂给现成的压缩算法，训练器与 rollout 引擎之间要通信的数据量直接降到千分之一。

“The updates themselves are incredibly sparse. 100X or 1,000X as sparse.”更新本身极度稀疏，稀疏 100 倍甚至 1000 倍。

于是推理 GPU 可以搬到集群之外。演讲者提到的那次 Qwen 训练就是这么跑的：训练集群落在 GCP，推理 GPU 则分布在整个算力舰队里，横跨各家超大规模云厂商与 Neo Cloud。稀疏差值压缩让这成为可能，而且没有带来性能损失。

7.2 异构算力与稳定训练

不只如此，rollout 舰队还按 GPU 类型切碎了。Modal 要服务不同客户对不同 GPU 的需求，能用上的 GPU 越多越好。代价是失配进一步放大：训练器跑在 B200 上，rollout 可能跑在 H100 或 A100 上，硬件差异本身就会让训练失稳。

这张图统计的是整次训练里各 GPU 类型处理的请求占比：B300 约 29%，B200 约 20%，H200（FP8）约 18%，其余由 H100、H200（BF16）、RTX PRO 6000 与 A100 分担。同一型号还有两种量化并存——H200 就有两个池子，一个跑 BF16，一个跑 FP8；修正必须连过度量化带来的失配一起盖住。

配方扛住了这份失配。演讲者的说法是：失配放大到四五倍，训练奖励与梯度范数仍然与同构情形（训练与推理全在 B200 上）一样稳定。图里四块面板——训练奖励、每 token 的 KL（采样器对训练器）、梯度范数与熵——混合采样器与同构采样器的曲线几乎重合。

还有个附带的好处：这次完整训练的 rollout 便宜了约 15%。高端 GPU 需求大、价格高，能在需求低的便宜硬件上跑 rollout，整次训练的成本就显著下降——这还是在没有针对每种 GPU 单独调推理的前提下，只用现成的推理配方；如果再按 GPU 类型分别优化量化，还能更便宜。

8. 收束：拥有整条栈

演讲的收尾回到开场的问题：要竞争，就要拥有整条栈，至少要在栈的每一层都建立能力。演讲者说，传统工作往往止于 Agent 脚手架，但在竞争激烈的行业里，跨越全部层面的垂直整合极其重要——编码是这样，其他行业也正在跟上。

这份配方已经发布：博客里有全部技术细节，源代码也即将发布，基于 Miles 强化学习框架与 SGLang 推理引擎。演讲者的收尾只有一句话：你应该拥有自己的 Agent 的 RL；现在这已经可行，因为这门科学已经被摸透了，而且有很好的工具与基础设施帮你做到。

“You should own your own agent in RL. And it’s actually possible now because the science has been figured out.”你应该拥有自己的 Agent 的 RL；现在这已经可行，因为这门科学已经被摸透了。
