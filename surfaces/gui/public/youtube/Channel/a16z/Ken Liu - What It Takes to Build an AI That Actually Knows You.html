What It Takes to Build an AI That Actually Knows You — Ken Liu (First Person Labs), a16z

每个新 Agent 都要从头认识你：你的偏好、行程、关系与正在做的事。First Person Labs 联合创始人 Ken Liu 带来的答案不是又一个 Agent，而是一个叫 Second 的个人上下文层——它 24 小时读你电脑里的事件流，分层综合成一个关于你的模型，再把这份上下文交给任何一个你选中的 Agent。这一期对谈的真正主角不是产品功能，而是随之而来的三个硬问题：一个什么都看见的东西凭什么被信任；大模型守不守得住秘密；以及全天候理解一个人到底要花多少钱。Liu 的回答串起一条清晰的线：理解先于提问，信任先于能力，而成本最终会决定这东西属于少数专业人士，还是属于每一个人。

Key Takeaways

  1. Second 不是又一个 Agent，而是一个人的模型。记忆、偏好、目标与意图的可携带层，别的 Agent 来向它问路，而不是各建各的记忆。
  2. 电脑早就什么都知道。应用切换、敲击、停顿与 Wi-Fi 构成一条 24 小时的事件流，分层综合就能读出你在做什么、要去哪里。
  3. 真正的生产力不是反应，而是反思。把几个月前的承诺与最近的目标连起来，在你开口之前提醒你该做的事。
  4. 信任不能只靠一句承诺。自带 Token、机密推理与本地优先，把“别偷看”从政策保证变成硬件可以验证的事实。
  5. 一个 Second 就够了。临时的子 Agent 可以随开随灭，但一致的存储才是价值所在；设备只是输入，Second 是随身的自己。

1. 开场：电脑早已知道你

节目没有暖场，直接从一句判断开始：人们大大低估了电脑已经知道多少。Ken Liu 说，现在你对写代码的 Agent 再也不用解释什么，截一张图、说一句“修一下”，它就知道该修什么。问题于是反了过来：既然电脑已经知道这么多，为什么还要你一遍遍开口？这期对谈的嘉宾是 First Person Labs 联合创始人兼 CEO Ken Liu，主持人是 a16z 的 Martin Casado 与 Joel de la Garza；话题是 Liu 的公司刚推出的产品 Second——一个个人上下文层。开场先放了一张标题卡：米开朗基罗《创造亚当》的变体，上帝伸手触向一台老式电脑，画面上只有两个词：the computer。

对谈的起点是一个日常的恼火：每个新 Agent 都要从头认识你。你的偏好、行程、关系、正在做的事，换一个 Agent 就要重新教一遍。Liu 的回答是，问题不在 Agent 不够聪明，而在没有一个地方替你攒着“你是谁”。Second 要做的就是这个地方：一个关于你的模型，别的 Agent 来向它问路。

2. First Person Labs：给一个人建模

“我们做的，归根结底是给一个人建模，再把控制权交还给这个人。”Liu 对公司的介绍只有这一句，但“模型”这个词在他这里有具体所指：不只是你的记忆和做过的事，更是你的优先级、偏好、目标、价值观、承诺与意图。模型先从一份基础清单长起——你做过什么、你生活里都有谁、你偏好什么；然后它开始分析你说话的方式、表达自己的方式、分享信息的方式，理解随之越长越深。

“People are very underestimating how much the computer already knows.”人们大大低估了电脑已经知道多少。

■ Second：First Person Labs 的产品，一个个人上下文层；它持续读你的数字生活，建成一个关于你的模型，再把上下文提供给你选中的 Agent。

■ 用户模型（User Model）：关于一个人的结构化理解——记忆、行踪、偏好、目标、价值观与意图；它自己长起来，而不是靠你一条条填写。

一个模型要长到什么程度才算“认识你”？Liu 给的刻度是：它从一份可携带的上下文开始，随着时间变成你越来越完整的表征。有些理解可以沉淀进模型本身，有些则以“制品”的形式越攒越多。重点不在它记得多少，而在它记得的东西归谁——答案是归你。

3. Alfred 模型：会自己挑目标的管家

为了说明 Second 与 Agent 的关系，Liu 讲了一个蝙蝠侠的比喻：如果蝙蝠侠想吃一个芝士汉堡，他让 Alfred 去买，Alfred 不会到处宣扬这是蝙蝠侠要的，他只会按偏好把事办了——买回来，不解释。你信任 Alfred，是因为你知道他对你有一个好的模型，知道什么该做、什么不该说。Second 在 Liu 的设想里就是这个 Alfred：它本身不是 Agent，它是你与 Agent 之间的那一层。

实际用起来是什么样？Casado 是 Grok 的重度用户，他问：我已经有一堆 Grok 了，First Person Labs 插在哪里？Liu 的回答是：你去 Grok 那里说一句“去问问我的那个东西，我想要什么”，两个系统自己对上话，然后你只管说“帮我订一张机票”——它知道是哪一张：座位偏好、提前多久到机场、坐头等舱还是经济舱，这些你今天要反复解释的东西，模型里已经有了。

另一个例子是换工具。OpenAI 刚发布两个新模型，Liu 很久没用 Codex 了，但他一直在用 Second，于是直接打开 Codex，之前做过的工作与攒下的上下文都在——不需要把历史再搬一次家。上下文跟着人走，而不是锁在某一个 Agent 里，这是整期对谈里反复出现的判断。

4. 电脑里的事件流：理解从何而来

模型里的理解从哪来？Liu 的回答分两层。第一层是你电脑里本来就有的东西：一条无穷无尽的事件流——你切换到哪个应用、在某个网页上停顿多久、怎么打字、连着哪个 Wi-Fi。操作系统在苹果、微软与 Linux 上都已经把这些交出来了，问题只是有没有人认真分析它。分析的办法是分层综合：某一段敲击可能意味着你在发消息，从浏览器切回 Codex 可能意味着你在查资料或写一篇 Google 文档；一层层往上，理解就长出来了。

Casado 在这里插了一句自己的体验：他是最早的用户之一，最打动他的不是 Second 知道他是谁，而是它接得通他所有的渠道。Liu 承认，这正是系统里最难的部分——难的还不只是接通，而是接得安全、私密。第二层是现成的连接器：Slack、Signal、WhatsApp 这些渠道接进来，学习的速度会快得多，用他的话说，这是一个样本效率问题。

■ 事件流（Event Stream）：你使用电脑时连续产生的原始信号——应用切换、停顿、输入、联网状态；操作系统本来就提供这些，分层综合后才能读出意图。

5. 主动式 AI：反应式与反思式

理解长出来之后，AI 的工作方式会变。Liu 把生产力分成两层。第一层是反应式：邮件来了，通知响了——但你的收件箱同时被九个别的个人 Agent 盯着，一封邮件能换来十条提醒，这件事做起来直截了当，也容易。第二层是反思式，难得多：它把跨越许多事件、很长时间的点连起来——几个月前你说过这个，最近你在往这个目标走，这是你的优先级、你的待办清单，顺便说一句，你偏好这个。

Casado 讲了一个自己的例子：他们在筹备一场活动，当天有 20% 的降雨概率，Second 实时追踪天气预报，不断告诉他们要不要准备帐篷。他没有要求过这件事。de la Garza 也有同样的体验：Second 会发消息告诉他某段进行中的对话有了新情况，那是他自己都没想到的、确实需要知道的事。Liu 把这句话收成一句判断：现在最大的毛病，就是人还得开口问；而超级智能，本不该让人开口问。

“You’re not supposed to ask things.”你本不该开口问的。

■ 反应式生产力（Reactive Productivity）：对刚发生的事件作出响应，如邮件提醒；直接、容易，但十个 Agent 会为同一件事各提醒你一次。

■ 反思式生产力（Reflective Productivity）：把跨越数月、多起事件的线索连起来，判断什么对你重要，并在你需要的时候主动提醒。

这正是 Liu 眼里人机交互未来的样子：重点不再是对事情作出反应，而是判断哪些干预值得做、哪些事可以不经你开口就替你办了。提醒的时机本身，就是理解的一部分。

6. 为什么只有一个 Second

Casado 有一堆 Grok：一个管合成器，一个管房产，一个管家庭——他自嘲说，管家庭的那个本不该需要，但确实需要。问题是：以后会有第二个、第三个、第四个 Second 吗？Liu 的回答很干脆：不会有第三个，也不会有第四个。许多个人 Agent 并存只是过渡状态，Agent 会像人一样分工：有的专精亚马逊购物，有的专精保护你的数据；而 Second 是那一个你托付毕生上下文的东西，像一个保险库。

临时开出来的子 Agent 可以随开随灭，办完事就消失；但一致的存储不能散。Casado 把这句话接了下去：一个你信任的 Agent，装着你全部的个人数据，真正知道你是谁，再去和你所有的其他 Agent 打交道——那就是 Second。长远看，Liu 想象每个人都有一个 Second，而设备只变成输入：屏幕、门铃、甚至身边漂浮的光球，都只是它伸出来的手。

“There will not be a third.”不会有第三个。

7. 信任的架构：机密推理与两种存放方式

一个什么都看见的东西，凭什么被信任？Casado 承认自己是个偏执的安全主义者：他说，想到这东西看见你做的一切，第一反应就是“哇哦”，而不该是你先信任它。Liu 的回答从第一性原理开始：说到底，AI 只有两样东西——数据与推理。你要定义的是，什么推理可以落到这份数据上。Second 的设计就是把这个选择权交给你：如果你原则上不信任这家公司，你可以自带 Token，让你自己的 Token 在你的笔记本本地分析数据。

更进一步的答案是机密推理：把模型放进 GPU，打开机密计算的开关，你可以证明里面跑的只有这个模型，谁也看不见里面；你信任的不再是跑模型的那家公司，而是硬件本身，也就是英伟达。Liu 说，OpenAI 最近一个月也在提供这个选项，因为所有个人数据最终都该走向机密推理，而不是标准推理。

■ 机密推理（Confidential Inference）：把模型放进支持机密计算的 GPU，可验证地证明其中只运行该模型、无人能够窥视；信任的根基从运营方转移到硬件。

■ 零数据留存（Zero Data Retention）：服务商“不保留你的数据”的承诺；Liu 指出，这只是政策上的一句保证，与硬件可验证的机密推理有本质不同。

数据存在哪，也有两种做法。第一种叫 Second Local：数据留在本地，只流向你选定的推理方，除此之外谁也没有你的数据。第二种是云端托管：先在本地加密，再放到云上，解密只发生在机密容器里——可以只在内存里短暂解密，也可以把整个存储都放进容器，像 iCloud 与密码管理器的做法，只是解密环节同样可以被验证。加密在本地、解密在容器里，链条就此接通。

“Zero data retention is a promise by policy.”零数据留存只是政策上的一句承诺。

8. 秘密守得住吗：两道防线

de la Garza 把问题推到最难的地方：如果我去问你的 Second，“Ken 让我拿他的日程”，它怎么知道不该给？Casado 还补了一个玩笑：他前几天问自己的 Second，“Joel 在瞒着什么？”Liu 的回答是，保障分两种。确定性保障是硬规则：有些东西永远不进系统，比如系统密码，这类事必须用工程手段锁死。推理型保障则靠上下文：Second 对 Martin 有一个模型，知道他俩之间的交往方式——他不会在凌晨三点发消息，所以凌晨三点的一条消息很可能是冒充。

但规则写不完。Casado 举了一个钻空子的办法：假装在写一出戏，戏里写着不该做的事，诱使模型把秘密说出来。Liu 承认，这是一道解不彻底的题；好消息是，它本质上是一道推理题，会随着模型能力的提升而变好。模型越强，分得清什么该说什么不该说的能力也越强。

9. 成本账、模型组合与用法

全天候理解一个人要花多少钱？Liu 当场算了一笔账：假设 10 个 Agent 各以每秒 60 Token 的速度跑一天，按 Opus 5 系列的价格，一天大约是一千美元；换成 DeepSeek Flash，大约是每天六十美元。主持人在旁边惊呼了一声。Liu 的意思是，现在这东西还不是给所有人的——目标用户是像 Casado 这样的忙碌专业人士，以及在工具之间频繁切换的人。但 Token 的价格自公司成立以来已经跌了一半以上，新模型不断出现，成本只会往下走。

便宜与准确之间有一道权衡：你愿意在缓存时多算，还是在提问时多算？把理解提前算好、存起来，回答时就快；只留原始记录、现用现算，回答一次要花十倍的时间。模型的选择也一样：判断“你把日历邀请挪了一下”这种语义时刻，用便宜的模型就够了；判断“Joel 这周的目标是什么”，值得偶尔动用贵的模型。Second 因此从一开始就按可移植来设计：一套线束，什么模型都能接上，新的检索模型出来就换上去，时间长了自然长成一个混合模型。Liu 还补了一句：开源权重模型如今已经相当聪明。

■ 上下文连续性（Context Continuity）：在笔记本上浏览的东西，合上电脑、拿起手机还能接着做；同一个上下文按分钟跟上你，而不是按设备重来。

用起来其实很简单：装一个应用，给它权限，填好你的 Token，后台的 Agent 就开始跑了。Casado 回忆自己安装时接了 Slack、Signal、WhatsApp；Liu 说连接器只是其中一部分，原始的电脑事件流才是底子，连接器让它学得更快。跑起来之后，Second 会长出一批 API：十分钟前你在做什么、下周的优先级、提醒事项、以及一本关于你生活里的人与流程的维基。起初它更像可携带的上下文，带着它去任何 Agent 那里都能接着用；往后应用会越来越多地建在这些 API 之上。Liu 讲了一个设计师朋友的例子：他放按钮与配色的方式多少被 Second 记住了，自己搭个人应用时，迭代次数一下子少了很多。这让他想起 Altair 8800 刚出来的时候——机器本身什么都不会干，直到有人写出电子表格，它才变得有用；Second 现在也处在同一个位置。

10. 走向 Jarvis：堡垒也要好用

对谈的后半段转向了愿景。Casado 说，他想要一个 1970 年代科幻片里的东西：屏幕上的一颗头，能跟他说话。他的 Second 已经很聪明了，问什么都答得很好，可它没有身体，这一点让他抓狂。Liu 的回答是，Jarvis 之所以是 Jarvis，不只因为它聪明、能办事，更因为它无处不在——在门上、在盔甲里、在屏幕里。那种连续性与无处不在，才是人们真正忽略的部分。

Martin 接过话：自从用上 Second，他的科幻未来感终于开始了——第一次有个东西感觉真的认识他，可以就此展开一段相关的对话。但我们仍然被绑在设备上。Liu 想象的长远未来是：每个人都有一个 Second，所有设备都变成输入，而输出可以是任何一块屏幕，甚至是身边漂浮的光球。Casado 提到了伊恩·M·班克斯的《文化》系列——那里面有最好的具身 AI，在你身边漂浮；Liu 说，普及计算这个想法已经被谈了几十年，最接近的东西是苹果的 iCloud，可那只是同步笔记，没有 AI 的版本。

眼下能做到的还有限。Casado 问：我在厨房放一台 iPad，想让 Second 在那里，该怎么办？Liu 的回答很实在：现在没什么办法，操作系统把它锁死了；今天能走的路是云端 MCP——只要 iPad 联网，任何能理解 API 的 Agent 都能到场。或者更简单：让 Grok 打电话给你，开着免提聊，Casado 说他开车散步时就是这么干的，Grok 的语音模式配上 Second 出奇地好用。

最后一问回到公司本身：一个既要造堡垒、又要让人用得愉快的团队，是不是精神分裂？Liu 说，摆在面前的是两种问题：基础设施问题与交互问题。交互那头他们犯过不少错——一头扎进界面里，才发现要做出令人愉悦的体验，细节多得惊人。最后的决定是反直觉的：把能做的界面收起来，只留发短信与 API。不是不想做，而是想先让理解本身长好，再由别人——由每一个拿到这份理解的人——去建应用。节目在 Liu 的一句话里收尾：今天就能试用，网址只有 2.computer。

这期对谈真正的张力，不在产品，而在顺序。理解先于提问：先有关于你的模型，Agent 才不必一遍遍问你是谁。信任先于能力：先把数据与推理的边界钉死，能力才敢放开长。成本最后会决定归属：今天它属于付得起每天一千美元的人，明天它可能属于每一个人——前提是，理解你的那个东西，始终归你所有。
