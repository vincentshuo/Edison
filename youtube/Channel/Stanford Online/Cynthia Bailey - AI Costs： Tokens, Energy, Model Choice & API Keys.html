数清每一枚 Token 的代价

AI Costs: Tokens, Energy, Model Choice & API Keys

Speaker: Cynthia Bailey，斯坦福大学高级讲师（Senior Lecturer），CS193T《Thinking with AI》主讲

Event: Stanford CS193T 第 7 讲

Length: 48 分 59 秒

Source: youtu.be/l07K2cdLofM

Technical Monograph · 精读报告 发布 2026 年 11 月 19 日 生成 2026 年 11 月 19 日

用 AI 要花多少钱？斯坦福 CS193T 第 7 讲把这个问题拆成四本账来算。Cynthia Bailey 先打开一张真实的 Claude Code 用量报告，逐行读出总费用、两种时长、输入与输出 Token、缓存读数与技能占用，说明缓存为什么能把价格打到九折以下；再把目光从账单移向电表与水表，引用谷歌自报的中等提示耗水耗电数字与图像、视频、推理模式的能耗倍数；然后讲多步 Agent 该怎么选模型——延迟会在每一步里重复计费，大不是答案，合适才是；最后现场演示一把 API 密钥是怎么从网页源码里漏出去的，并以一周前的中期选举收尾：数据中心的账，已经算进了选票里。

Key Takeaways

  1. 先读懂用量报告。API 时长、挂钟时长、输入与输出 Token、缓存读数，四组数字就是一张账单的全部结构。
  2. 缓存便宜是因为注意力只算一次。重复的上下文不必重新计算，缓存读取可比原始输入便宜约九成。
  3. 一次文本提示很便宜，但倍数很大。图像约数十倍、视频上千倍、推理模式平均约 30 倍，长上下文的账还要另算。
  4. 模型不是越大越好。延迟随规模走，多步流程里要乘以步数；客观规则配最便宜的模型，需要判断的护栏才配强的。
  5. API 密钥就是程序的登录密码。谁拿到它，谁就能记你的账；写进网页源码等于贴在墙上；数据中心的账，最后会出现在选票上。

1. 开场：先数星星，再数 Token

Bailey 以《小王子》里那个数星星的商人开场：他自认拥有星星，整天一本正经地数它们。这堂课要做的事与之相仿，只是数的是 Token。议程共五项：读一张 Claude Code 用量报告；算 AI 的电与水；为多步 Agent 选模型；讲 API 密钥；最后是一周前才加进来的新幻灯片——AI 数据中心与选举。本周工具仍是 Claude Code 与 Codex，另加 Hopscotch 与 OpenRouter 两个资源管理工具，用来在不同模型之间切换、比较与管理用量。CS193T 的全名是 Thinking with AI，Bailey 是斯坦福高级讲师，同时执教 CS106B，课上提到的 Wayfinder 助教工具正是她在 CS106B 里实际使用的系统。

这不是一堂抽象的原理课，而是一堂算账课。Bailey 的立场在开场就亮明了：Token 很抽象，水、电与碳足迹不抽象；美元账单看得见，资源账单同样要看。五项议程由近及远：从自己电脑上的一张报告出发，走到数据中心、走到选票，最后落到一句提醒——你在选模型、耗 Token 的时候，别人正在为要不要在你家附近建数据中心投票。

“So, we are going to be very serious and count all our token usage here.”所以，我们要非常严肃地数清我们在这里的全部 Token 用量。

2. 读懂一张用量报告：四组数字就是全部结构

在 Claude Code 的命令行界面输入 /usage，就能看到一张用量报告。Bailey 展示的示例报告总费用为 28.88 美元，总 API 时长 58 分 8 秒，挂钟时长 5 小时 57 分，代码改动为增加 2797 行、删除 498 行。两种时长的区别是理解账单的第一步：API 时长是等模型回应的时间总和，包括权重计算、网络往返，以及数据中心繁忙时排队造成的延迟，五十次提示的等待时间会累加进去；挂钟时长则单纯是自会话开始以来墙上时钟走过的时间，是计算机科学里衡量性能的常用口径，与 CPU 时间不同。

输入 Token 是模型在整个会话里读过的全部 Token，不只是你敲进去的提示词，还包括系统提示词、设置、已启用的工具连接器说明——凡是塞进上下文窗口的东西都算。输出 Token 是模型生成的全部 Token，包括你看得见的回答，也包括推理模型在给出答案之前内部的来回推演：模型之间的那场讨论本身也是概率性的 Token 生成，照样计入输出预算。报告按模型分列用量：示例中 Claude Haiku 5-5 只用了 1.2k 输入、19 输出，费用 0.0001 美元；Claude Opus 5-5 则是 31.0k 输入、313.5k 输出，外加 84.8m 缓存读取与 749.3k 缓存写入——大头全在 Opus 身上。

■ 挂钟时间（Wall-Clock Time）：墙上时钟走过的时间，即从开始到结束实际经过的时间，与 CPU 时间等只计计算耗时的口径不同。

缓存是这张报告里最值得花时间的一项。同一会话里，系统提示词、设置等上下文内容在每一次提示时几乎不变，却要随整个上下文窗口一次次重新处理；缓存的做法是把这部分预先算好存起来，下一条提示直接复用。便宜的原因在第一讲的注意力机制里：计算注意力要做一轮代价高昂的矩阵乘法，算一次、把结果存下、反复复用，就不必每 Token 都重算。报告显示，示例会话发起了 255 次请求，99% 的输入 Token 来自缓存、无一次未命中；缓存读取的价格可比原始输入 Token 低约九成。Bailey 用第一讲的例子说明这一点：当“老师说欢迎光临，请坐”把概率从饼干、饮料推向座位时，注意力机制给这几个词加了权——字体变大的那份已算好权重的文本，就是缓存里存的那份拷贝。

■ 提示缓存（Prompt Caching）：把会话中不变的上下文预先计算并保存，之后直接复用，免去重复处理；缓存读取因此比原始输入 Token 便宜得多。

■ 注意力机制（Attention Mechanism）：Transformer 中给不同 Token 分配不同权重的计算，是大模型成功的关键技术，也是缓存能省钱的根源——权重算一次即可复用。

报告的另一栏是插件与技能占用：每启用一个技能，它的提示词文本就进入上下文窗口，成为每次提示的固定成本。示例中只有一个技能类别、内含四个技能（Vercel），每轮提示注入约 225 个 Token；即使整个会话一次都没用过这个技能，这笔开销照付不误。所以 Bailey 的建议是定期清理启用的技能，不需要的就拿掉。报告末尾的三条建议与课上早已讲过的做法一一对应：给通用子 Agent 配更便宜的模型（Opus 的活分一部分给 Haiku）；换任务就开新会话，即运行 /clear；看清上下文窗口里装了什么，即运行 /context。幻灯片上还标出了三条建议在示例会话中的占比：94%、76% 与 17%。

3. 电与水：Token 之外的账

美元账单之外，Bailey 要求学生也看看资源账单。她先承认一个困难：数据基本不公开，研究者只能拿开源模型在自己的服务器上跑来估算。谷歌 2025 年自报的数字是：一次所谓“中等”文本提示，耗水 0.26 毫升、耗电 0.24 瓦时、排放二氧化碳当量 0.03 克，大约相当于看 9 秒电视。她提醒把“自报”二字放在心里：模型是不是变大了、推理是不是变多了，都会让这个数字往上走，而“中等提示”本身也没有精确定义。

真正让数字变大的是倍数关系。研究者发现，在同一提示、同一模型的比较中，倍数关系相当稳定，因此可以外推到看不见内部的商业模型：图像生成约为文本的 28 至 40 倍（引自《麻省理工科技评论》刊载的一项研究），视频生成约为文本的 1000 至 3000 倍，推理模式平均约为 30 倍，个别模型可达 150 倍乃至 700 倍。推理模式的倍数在不同模型间并不一致，Bailey 对此也持保留态度：外推到商业模型上是否成立，并不像图像与视频那样有把握。但从使用体验上看，推理模型必然生成更多 Token、做更多计算——屏幕上展开的思维链摘要本身就是证据，它只是最终答案之外那场漫长推演的梗概。

她补了一项容易被忽略的成本：长上下文。Epoch AI 做过测算，比较上下文窗口里放 1 万个输入 Token 与放 10 万个输入 Token 各要花多少钱——Bailey 在课上只点了这个题目，没有展开具体数字，意思是提醒学生：换话题就开新会话（new topic, new chat），不是卫生习惯，而是省钱的办法。上下文窗口塞得越满，每一次提示的账单就越重，缓存能省的是重复计算，省不掉你主动放进去的体量。

“Tokens is a little bit abstract, but water and electricity and carbon footprint are not abstract.”Token 有点抽象，但水、电与碳足迹一点也不抽象。

4. 选模型：大不是答案，延迟才是

模型越大能力越强，但回答也越慢，这个等待时间叫延迟。延迟之所以关键，是因为它会在多步流程里重复计费：总 API 时长本质上就是会话中全部提示的延迟之和；一个五步的 Agent 流程里，单步慢一点，总时长就要慢五倍。哪怕完全不考虑环境与金钱，只考虑使用体验，大也不等于好。幻灯片把这一点写成标题：Bigger is not always better——更小的模型按 Token 更便宜、算力更少、对环境更友好，而且延迟更低。

案例一是 Bailey 自己的 Wayfinder 助教系统，斯坦福 CS106B 课程实际使用的 AI 辅导工具，目标是防止助教直接把作业答案交出去。流程分三段：输入护栏 Agent 先检查学生的问题是不是直白地索要答案，通过才放行，否则回一段写好的提示，引导学生换个更利于学习的概念性问题；回答生成 Agent 再给出经过微调的、带课程资料引用与趣味类比的回答，甚至与学生展开苏格拉底式对话；输出护栏 Agent 最后检查生成的回答，确保其中没有答案。输出护栏发现问题时会把回答打回给回答生成 Agent 重做，实测中有时要来回数次才通过——延迟的账，就是在这里被乘以五倍的。

Bailey 请学生现场讨论：斯坦福 AI Playground 提供的 OpenAI 模型里，GPT-6 一代的 Soul、Luna、Astra 与上一代的 GPT-5.6 Soul，各该派给哪一段、为什么？便宜有两个维度：同一代里型号越小越便宜，代际越新，能力与价格也不同。她的答案藏在第二个案例里：斯坦福内部有一个公司政策问答聊天系统，背后是检索了全部员工与教职手册的知识库，学生问休假审批、人因项目合规，系统都要给出带引用的准确回答。这里的输出护栏 Agent 与 Wayfinder 的输出护栏同名，但责任完全不同：Wayfinder 的标准客观而明确——回答里不能出现超过连续三行的代码，最小、最便宜的模型就能胜任；政策问答的护栏则要结合员工的具体情境、细读政策文本、核对引用是否真实支持结论，与回答生成 Agent 负有同等的判断责任，容不得半点含糊——律师把不存在的引用写进法庭文件、或者引用真实但论证完全走样的新闻，Bailey 认为是同一类错误的现实版。同一个职位名称，选型结论截然相反：这正是“按任务选模型”的全部含义。

■ 延迟（Latency）：从发出提示到拿到结果所需的时间，随模型规模增大而上升；在多步 Agent 流程里，每一步的延迟都会累加进总时长。

■ 护栏 Agent（Guardrail Agent）：在流程入口或出口做检查的 Agent，只负责放行或拦截，不负责生成主要回答；其选型取决于检查标准是客观规则还是需要判断的 nuanced 分析。

5. API 密钥：程序的登录密码

API 密钥是另一种使用模型的方式：不在聊天窗口里用，而是在程序里调用。API 是应用程序编程接口（Application Programming Interface）的缩写，是给程序用的接口，不是给人用的界面。理解它的最简单办法是把它看作登录凭证：你用人名与密码登录账户，程序就用 API 密钥登录同一个账户，模型的使用费记在谁的账上，由它说了算。免费账户、高级账户的区分也由它来识别。Bailey 用自己 550 人的大课举例：她要给全班提供 Wayfinder 助教机器人，费用有两种分担方式。一是她提供自己的 API 密钥、绑自己的信用卡，全班免费使用——她最终选了这一种，因为想让工具对所有人平等开放；二是每个学生自己去注册密钥、绑自己的信用卡，用多少付多少，成本随使用分摊到每个人头上。后一种方式让工具的制作者不必独自承担全部费用，也能把工具提供给别人，这是 API 密钥带来的分布式成本分担。

但与登录密码一样，API 密钥需要同等级别的保护：不要贴在公共场所的便利贴上，不要用短信发送。最常见的翻车场景发生在 vibe coding 里：学生做一个带 AI 功能的网站，愿意替所有访客付费，于是把密钥写进网站代码——而网站代码是任何人都能看到的。Bailey 现场演示了一个她自己 vibe coding 的“海盗翻译器”网站：输入一句天气，点按翻译按钮，网站把文本发给 Claude Opus 5.5，返回一段海盗腔的译文。演示用的密钥是假的——她再三强调，真的密钥绝不能出现在这里。但点按之后返回的是“API 密钥无效”，因为演示没有放真密钥；随即她右键查看页面源代码，逐行读出 HTML：海盗字体、旗帜图标、输入框、按钮，再到点击按钮时执行的 JSON 请求——其中赫然写着 const apiKey 等于一串形如精心编造的密码的字符。任何人只要拍下这张幻灯片，就能把这把钥匙抄进任何工具，让账单记到她的头上。

正确的做法是把密钥妥善藏在公众视线之外：网站可以公开使用，但密钥本身不能公开。Bailey 的建议是，如果自己没有把握，就让代码审查工具（她称之为 code review goldfish）检查一遍，确认密钥没有泄露。课后附有一组幻灯片，把这次演示的步骤完整走了一遍，供学生复习。她留下的最后一句话是希望自己已经把学生吓够了，让他们永远不再犯这个错误。

“You would want to treat an API key with the same kind of protective caution that you would treat any of your normal human passwords.”对待 API 密钥，要像对待你任何一个常用的人类密码那样谨慎。

■ API 密钥（API Key）：程序调用模型时使用的登录凭证，决定费用记在谁的账上；与人类密码同等重要，泄露后他人可盗用额度。

6. 尾声：数据中心走进选票

讲座的最后一节是上周才加进来的时事。2026 年 11 月 3 日的中期选举里，AI 数据中心成了议题。Bailey 先讲了一个具体地点：犹他州盐湖城以北的乡村，Shark Tank 明星投资人 Kevin O’Leary 计划建一座巨型数据中心，遭到当地居民强烈反对——占地广、又处在用水紧张的地区，而大盐湖正在干涸，数据中心正好位于注入盐湖的水源上游。反对声里还有噪音：为 GPU 散热要耗水耗电，柴油发电机运转起来非常吵。Bailey 提到《周六夜现场》还为此做了小品，让演员扮演 O’Leary 说，只想买下四万英亩上帝 untouched 的壮丽风光，换成一台很吵、会偷走你工作的电脑。

选举结果按 Bailey 引用的统计是压倒性的：11 月 3 日当天，10 个州有 41 项与 AI 数据中心有关的公投；把 2026 年内早些时候与 12 月的计算在内，全年 13 个州共 50 项（Ballotpedia 统计）。CNBC 出口民调显示，56% 的选民称 AI 与数据中心是投票时的关键或重要因素；CBS 出口民调显示，76% 的选民反对在自己社区建数据中心；提及数据中心的电视广告总值超过 3.8 亿美元（Telegraph 统计）。41 项公投中 40 项的结果不利于数据中心——有些是投赞成票、有些是投反对票，但方向一致。得州州长 Greg Abbott 与挑战者 Gina Hinojosa 的竞选中，数据中心是核心议题之一，而得州原本是最欢迎新建数据中心作为经济发展引擎的州之一。

Bailey 的收束把选举与课堂主题连在一起：选民不想要的，是高 Token 消耗、高电力消耗的模型——至少不想要以在他们社区建数据中心为代价。选举之夜过后、11 月 4 日，重仓数据中心的 Elon Musk 发推文称“data centers in space looking pretty appealing right now”，Bailey 的解读是：地球上已经没有地方想要它们了，也许该考虑把它们放进太空。讲座到此结束，留给学生的思考是：下一次选模型、耗 Token 的时候，账单不只寄给自己。
