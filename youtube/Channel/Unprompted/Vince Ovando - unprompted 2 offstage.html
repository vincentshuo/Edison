Prompt Injection Is Not a Vulnerability — Vince Ovando (AI Security Researcher), [un]prompted 2, 2026 offstage

Speaker: Vince Ovando，AI 安全研究员，Cybershark Consulting 创始人；主持 Aaron Mog，ZeroSum 主持人

十分钟的访谈，讲的是一个反常识的结论。AI 安全研究员 Vince Ovando 坐在 [un]prompted 的红色沙发上，讲他约半年前完成的一篇论文：在约 600 万次推理、四个模型家族、参数 17 亿到 1220 亿的实验里，他以可证明的方式证实，提示注入不是一个真实存在的漏洞——问题全在 Agent 外层的护栏怎么搭。访谈后半段，他把这个结论摊开成一套工程标准：别一上来就用大模型，先走确定性代码、启发式、嵌入这些台阶；用大模型给小模型写指令；造东西的标准是 100% 可靠，70% 能用不算解法；而下一波要谈的，将是针对各自场景的护栏工程。

Key Takeaways

  1. 提示注入不是漏洞，是护栏的问题。约 600 万次推理、四个模型家族、17 亿至 1220 亿参数的实验后，Ovando 的结论是：唯一可证明 100% 挡住恶意生成的控制在生成层，不在模型本身。
  2. 别一上来就用大模型。确定性代码、启发式、嵌入这些台阶在前，语法约束解码是其中一环；懂这套分层的人一听就懂，不懂的人只会攻击这个结论。
  3. 大模型是用来给小模型写指令的。日常做法是知识图谱加语法，用更强的模型把指令蒸馏给更小的模型；他来会场是想看看有没有同路人，结果没看到几个。
  4. 70% 可靠不算解法。他造东西的标准是 100% 可靠：让模型不可能失败，让员工不可能失败，让客户不可能失败。
  5. 下一波是护栏工程。上届会的共识已是护栏比模型重要；一年后人人谈的将是针对各自场景的护栏工程，而前沿实验室的护城河正因必须赚钱而迅速消散。

1. 开场与论文：提示注入不是漏洞

主持人 Aaron Mog 开场先道谢，请 Ovando 向不认识他的人介绍自己：是什么把他带到这里。Ovando 的自我介绍只有一句定性——他骨子里是个 nerd——然后是工作内容：AI 安全工程，进攻与防守两边都做；眼下的主要精力在语法约束解码与知识图谱上，用在能自我学习的自主红队与蓝队 Agent 上。

他此行要讲的演讲，源于约半年前完成的一篇论文。实验规模是他整场访谈里最硬的一组数字：约 600 万次独立推理，跨四个模型家族，参数从 17 亿到 1220 亿。结论只有一个：他以可证明的方式证实，提示注入不是一个真实存在的漏洞，问题全在护栏怎么搭。会场议程给这场演讲的标题是“The Model Is NOT a Security Control: Prompt Injection Dies at the Token Sampler”——模型不是安全控制，提示注入死于采样器。

■ 提示注入（Prompt Injection）：攻击者把指令藏进模型读取的不可信文本，诱使模型越权行动；Ovando 的论点是，这类攻击能否得逞，取决于外层架构，而非模型本身。

■ 语法约束解码（Grammar-Constrained Decoding, GCD）：解码时按预定语法限制模型每一步能生成的 token，只允许合规的工具调用与参数；Ovando 论文中唯一可证明挡住恶意生成的控制。

这个结论的锋芒在于它挪动了责任的位置。行业里常见的思路是把模型本身当作安全边界——更好的模型、更好的检测器；而 Ovando 的说法是，注入之所以成立，是因为护栏允许不可信文本一路走到能触发真实操作的位置。把生成本身锁死在授权的语法里，恶意内容就永远没有机会被“生成”出来。

“I provably proved that prompt injection is not a real vulnerability and it is all in how you architect your harness.”我以可证明的方式证实：提示注入不是一个真实存在的漏洞，一切取决于你如何搭建护栏。

2. 反响：懂的人爱，不懂的人攻击

这个结论在会场上相当有争议，Ovando 自己也承认，它“完全有争议”。他给出的解释是，不同的人在解不同的问题，大公司的需求当然不同；但对绝大多数人来说，问题出在起点：用 Agent 解任何问题，人们都直接跳进大语言模型，而在那之前还有好几级台阶——确定性代码、启发式、嵌入，诸如此类。

懂这套分层的人一听就懂。当天早些时候，他和一个人聊了六个小时，没去听任何一场演讲，只是在互相交换实战故事。反之，没有这套心智模型的人，连理解这个结论的框架都没有。Ovando 的总结很直白：不懂的人攻击他，略懂的人喜欢它；他要搭的正是中间这座桥。

“People who don’t understand attack me. People who have a vague understanding love it.”不懂的人攻击我，略懂的人喜欢它。

Mog 说他读过这篇论文，觉得很有意思；眼下正是争论的好时候，因为没人知道方向在哪里，一片混沌。Ovando 的回应是，他每天做的就是这件事——这不是一个只在论文里的想法。

3. 日常做法：大模型给小模型写指令

Mog 问他来会场最想学什么、想深挖什么。Ovando 的回答是，他每天做的事大体就是这套做法：大多数问题用知识图谱加语法就能解决；语法只有在出于效率考虑时才需要。更具体地说，他用更强的模型为更小的模型蒸馏指令，让小模型按指令行事。

■ 知识图谱（Knowledge Graph）：以实体与关系组织知识的结构化表示；Ovando 日常解题的主要工具之一，常与语法约束解码配合使用。

■ 蒸馏（Distillation）：用更强的模型为更小的模型生成指令或训练信号，使小模型获得接近前沿的能力；此处指指令层面的蒸馏，而非完整再训练。

他来 [un]prompted，是想看看有没有别人在做同样的事；结果是没看到几个在往这个方向推边界的人。会场上也有让他觉得值得未来研究的方向，但眼下不是他的重点。

Mog 接了一句：在前沿地带，环顾四周发现自己一个人，是常事。Ovando 没有反驳——这句话几乎是他整场访谈处境的注脚。

4. 共识与落差：前沿智能要装进小模型

Mog 把话题引向“叠 AI”：用前沿模型造出在小模型上更可靠的解法；观众是不是也想自己动手、自己搭开源权重方案？Ovando 说，他在会场上看到一个跨越所有人的共同点：不管来自哪里，大家都想从更小的模型里榨出前沿级别的智能，而且是能自己托管的模型。解法已经存在，只是大多数人还没去探索它。

■ 开源权重模型（Open-Weight Model）：权重公开、可自行下载与托管的模型；与必须调用厂商 API 的闭源前沿模型相对。

Mog 追问为什么：是不是因为用 Anthropic、OpenAI 太方便，成本又被补贴着？Ovando 说他也不知道确切原因——信息都在外面，免费可得；语法就是结构化输出，免费、公开。但现实是，人们被催着拿出答案、拿出解法，而给小模型、本地模型调优需要动手折腾；有些人没有这个时间，也没有这个余裕。他们要的是“大多数时候能用”的东西。

这正是 Ovando 与“大多数时候能用”分道扬镳的地方。他的标准是 100%：让模型不可能失败，让员工不可能失败，让客户不可能失败——这是他动手造东西时的心智模式。70% 的时间能用的解法，在他看来根本不是解法。

“I’m building for solutions that work 100% of the time. Make it impossible for the model to fail. Make it impossible for your employees to fail. Make it impossible for your clients to fail.”我造的是 100% 可靠的解法。要让模型不可能失败，让员工不可能失败，让客户不可能失败。

5. 下一波：护栏工程与护城河的消散

访谈进行到约第 6 分钟，Mog 把话题转向“下一波”：这阵子很糟糕——额外的工作、混乱、PHP 相关的问题、模型层出不穷；大家又处在一个巨大的炒作周期里，下一个流行词会是什么？Ovando 说，流行词留给市场营销的人。但他没参加上一届会，听到的共识是：人们终于开始明白，护栏工程比模型本身重要得多。

■ 护栏工程（Harness Engineering）：模型之外的一层工程：工具、权限、凭证、运行环境与审批，决定 Agent 能接触什么、能做什么；Ovando 认为它比模型选择更重要。

顺着这个共识再往前走一步，现在的问题变成：有了对护栏的控制，怎么把前沿模型的智能搬到更小的模型上。他预计，一年之后，人人谈的都将是针对各自场景的护栏工程。与此同时，前沿实验室的护城河正在迅速消散——因为它们必须开始赚钱，而现在很多能力是被补贴着的；人们找到替代方案的速度，会比以往任何时候都快。

“The moat for these frontier labs is quickly dissipating because they have to start making money.”这些前沿实验室的护城河正在迅速消散，因为它们必须开始赚钱了。

Mog 接过“稀缺催生创新”：现在 token 很便宜，挤压的必要性不大；六个月或一年之后，同一场会讨论的将是如何从 token 花费里榨出更多。眼下还没到人人抱怨“我的 AI 账单太大了”的阶段，但那个阶段正在靠近。

6. 语法的出路：让上下文更便宜

Mog 最后问到语法这条“泳道”：它会不会热起来，会不会被产品化——比如变成 AI 网关？Ovando 说，语法已经存在多年，至今仍是很小众的话题，而它本不该如此。他想看到的是，人们去探索让上下文更高效的办法。

他举的例子很具体：现在 AI 探索代码库的做法，是派出一群子 Agent 去 grep、做模式匹配、把碎片拼起来；与之相对，可以用现成的命令行工具直接生成代码的调用图，让 Agent 去用这些工具。于是就不需要花 1500 万个 token、30 分钟、一群子 Agent 去摸清一个新代码库——一个 Agent 15 秒就能拿到它需要的全部上下文，花的 token 少得多。

■ 调用图（Call Graph）：代码中函数互相调用的关系图；现成命令行工具可直接生成，Ovando 主张让 Agent 用它，而非靠子 Agent 群穷举。

“A singular agent can get all the context it needs in 15 seconds.”一个 Agent 15 秒就能拿到它需要的全部上下文。

在他看来，这也是护栏工程的一部分：让 Agent 不可能失败。至于“token maxing”之类的叫法，他并不在意名词；重点是让工具更高效，而不是只让模型本身更高效——无论选哪个模型，这个方向都成立。

Mog 收尾时说，他很期待看 Ovando 的演讲，也很喜欢读他写的材料。Ovando 回了一句：“Appreciate it, buddy.”十分钟的访谈到此结束，留下的是一个尚未被会场多数人接住、却已经有实验数据撑腰的结论。
